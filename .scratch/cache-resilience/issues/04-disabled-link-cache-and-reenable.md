# 04: 已禁用映射复用 403，受控重新启用立即生效

**What to build:** 已禁用映射短时间复用 403；维护者数据库提交并完成受控协调后，新开始的请求按当前启用状态判断，已到期映射仍返回 410。

## Acceptance criteria

- [ ] 未过期但已禁用时缓存独立 403 结果，保留业务过期时间；TTL 上限默认 15 秒，实际抖动为 13.5～15 秒，命中不续期。
- [ ] 403 缓存到业务过期时返回 410，复用 03 的已过期结果与过期判断能力，保持过期优先于禁用。
- [ ] SQL 状态维护提交后执行受控版本协调，分别报告数据库变更和操作完成；只有协调确认后才报告完成，不新增公开维护 API。
- [ ] 复用 02 的按短码协调恢复能力，未确认时允许重试；恢复只更新版本及清除缓存结果，不重新设置旧 enabled 值，不重新创建映射。
- [ ] 旧的已禁用查询在重新启用完成后迟到回填被拒绝；完成后才开始的新请求不受旧 403 影响。
- [ ] 多个独立实例共享同一 MySQL 主写库及 Redis 时使用同一协议；正常未过期映射重新启用后返回 302，已到期映射仍为 410。
- [ ] HTTP／真实 MySQL／Redis 验证禁用 miss／hit、TTL、SQL 次数、受控状态维护、协调失败恢复及数据库状态不会被旧恢复步骤覆盖。
- [ ] 维护说明明确：仅 COMMIT、仅 DEL 或绕过受控流程的直接 SQL 不能被描述为阶段 4 操作完成。

## Comments

- 按用户确认的阶段 4 拆分发布。02 提供可复用的协调恢复入口，03 提供已过期结果和边界处理；这两个直接前置共同覆盖 01。
