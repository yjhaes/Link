# 04: 已禁用映射复用 403，受控重新启用立即生效

**What to build:** 已禁用映射短时间复用 403；维护者数据库提交并完成受控协调后，新开始的请求按当前启用状态判断，已到期映射仍返回 410。

## Acceptance criteria

- [x] 未过期但已禁用时缓存独立 403 结果，保留业务过期时间；TTL 上限默认 15 秒，实际抖动为 13.5～15 秒，命中不续期。
- [x] 403 缓存到业务过期时返回 410，复用 03 的已过期结果与过期判断能力，保持过期优先于禁用。
- [x] SQL 状态维护提交后执行受控版本协调，分别报告数据库变更和操作完成；只有协调确认后才报告完成，不新增公开维护 API。
- [x] 复用 02 的按短码协调恢复能力，未确认时允许重试；恢复只更新版本及清除缓存结果，不重新设置旧 enabled 值，不重新创建映射。

- [x] 多个独立实例共享同一 MySQL 主写库及 Redis 时使用同一协议；正常未过期映射重新启用后返回 302，已到期映射仍为 410。
- [x] HTTP／真实 MySQL／Redis 验证禁用 miss／hit、TTL、SQL 次数、受控状态维护、协调失败恢复及数据库状态不会被旧恢复步骤覆盖。

## Answer

- 禁用映射回填独立 DISABLED 结果，保留业务 expiresAt、不包含原始 URL。配置 `short-link.redirect-cache.disabled-ttl` / `SHORT_LINK_DISABLED_CACHE_TTL` 默认 15 秒，向下抖动到 13.5～15 秒；命中不查库、不续期。
- REDIRECT 与 DISABLED 缓存命中共用业务过期检查，到期当刻返回 410，并按 generation 条件写入 EXPIRED，旧版本更新不能覆盖维护后的缓存。
- 复用内部 `recoverCacheCoordination`，SQL 提交后轮换版本并清除结果，正常返回才报告完成。README 区分数据库已提交与操作完成，明确仅 COMMIT、仅 DEL、绕过受控流程的 SQL 不代表完成；未确认时按同码重试，不重新设置 enabled、不插入映射。
- 真实 HTTP/MySQL/Redis 测试覆盖禁用 miss/hit、TTL 和 SQL 次数、缓存自然到期、禁用快照到期转 410、协调失败与执行后响应丢失、重复恢复、后续状态变更保留、已到期映射重新启用仍为 410。
- 独立 Spring 应用上下文共享同一 MySQL/Redis，用闩锁暂停旧禁用查询，重新启用并确认协调后新请求返回 302；旧重叠请求允许返回 403，但迟到旧回填被拒绝。
