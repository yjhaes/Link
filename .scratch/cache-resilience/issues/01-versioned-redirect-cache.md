# 01: 有效短链接通过版本化缓存保持正确跳转

**What to build:** 有效短链接继续通过 Redis 加速并返回正确的 302；缓存过期、条目丢失或被替换后，旧查询不能无条件恢复旧缓存。为后续拒绝结果、创建协调和请求合并提供相同的版本协议。

## Acceptance criteria

- [ ] 新缓存格式和读取结果准确区分 miss、无业务结果占位及可跳转快照，并支持后续三类拒绝结果的协议表达；占位不能返回 404。
- [ ] 版本初始化、条件回填和版本更换具备原子语义；版本与结果位于同一个有限 TTL 条目中，条目丢失后旧回填失败，新初始化不复用旧版本。
- [ ] 永久正值保持可配置的 5 分钟上限，写入时随机向下缩短 0%～10%；限时正值不超过业务剩余有效时长，命中不续期，应用保持精确过期判断。
- [ ] 302、Location、Cache-Control: no-store、短码大小写及非法格式通过现有行为回归；Redis 读失败回源，回填失败不改变 MySQL 结果。
- [ ] 真实 Redis 验证新结构序列化、有限 TTL、占位语义和旧版本条件回填失败；SQL 次数证明有效 hit 不查 MySQL。
- [ ] 第一张任务的接口调整及调用方迁移保持有效跳转路径可独立验证，不提前实现后续任务的 404 缓存或创建部分完成响应。

## Comments

- 按用户确认的阶段 4 拆分发布；本任务聚焦已有跳转读链路和可被业务流程调用的协调能力，创建后的完成与恢复流程由 02 接入。
