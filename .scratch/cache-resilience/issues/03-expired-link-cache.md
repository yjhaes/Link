# 03: 已过期映射复用 410，保留业务到期边界

**What to build:** 重复访问已过期映射不再反复查询数据库，同时可跳转快照在业务到期当刻仍返回 410，不因缓存寿命而继续跳转。

## Acceptance criteria

- [x] MySQL 确认为已过期时写入独立 410 结果，TTL 上限默认 5 分钟，实际抖动为 270～300 秒；后续命中不查 MySQL，命中不续期。
- [x] 过期结果、不存在结果和可跳转结果保持明确区分；过期优先于禁用，不把数据库中仍存在的已过期映射描述为不存在。
- [x] 用可控时钟验证业务到期前、到期当刻及之后的行为；正值 TTL 和业务有效期不混淆，到期后不继续返回 302。
- [x] 业务过期产生的结果更新也遵守版本条件，不能覆盖变更后或重新初始化的缓存条目。
- [x] 服务层及 HTTP／真实 Redis／MySQL 验证 410 miss／hit、TTL、SQL 次数及拒绝缓存自然到期后的回源。
- [x] 本任务基于 01 的共同版本协议可独立开展，不需要先完成 02 的 404 缓存或创建 503 恢复交付。

## Comments

- 按用户确认的阶段 4 拆分发布。01 完成后，本任务与 02 都处于可开展的前沿；实际协作仍需协调共享代码的修改。

## Answer

- MySQL 确认已过期时按当前 generation 写入独立 EXPIRED 结果；后续返回 410，不查询 MySQL、不续期。过期仍优先于禁用，与不存在结果保持区分。
- 新增 `short-link.redirect-cache.expired-ttl`（环境变量 `SHORT_LINK_EXPIRED_CACHE_TTL`），默认 5 分钟，抖动范围为 270～300 秒，独立于正缓存 TTL。
- 正缓存每次命中检查业务到期；到期当刻和之后返回 410，并通过版本条件转换为过期结果，不能覆盖已轮换或重新初始化的条目。
- 完整 Maven 测试 80 项通过，0 失败、0 错误、0 跳过；其中真实 Redis/MySQL 集成测试 24 项，覆盖 HTTP 410 miss/hit、TTL 不续期、SQL 次数、自然到期回源及旧版本更新拒绝。可控时钟及随机源验证到期边界与抖动端点。
- Standards Review、Spec Review 均使用 GPT-6.1 Sol、high；规范审查指出的重复测试辅助函数已提取，受影响的 4 项测试再次通过。
