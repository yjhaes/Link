# 阶段 4：已确认任务拆分

用户已确认本拆分的任务粒度、阻塞关系及交付范围。六张任务已分别发布为独立的本地 Markdown issue，状态均为 ready-for-agent；本轮仅发布任务，尚未开始执行。

## 拆分原则

- 每张任务贯通业务入口、持久层交互、缓存协议及对应验收，交付可以演示或独立验证的行为。
- 前置缓存接口和结果表达调整纳入第一张有效跳转任务，避免只有接口定义而无法验证业务行为的交付。
- 服务层行为测试与必要的 HTTP／真实 Redis／MySQL 验证随各任务完成；故障恢复任务交付实际的受控恢复流程，不代替其他任务的常规验收。
- 所有任务沿用规格中的配置和边界：三类拒绝 TTL 上限 30 秒／15 秒／5 分钟，向下抖动 0%～10%，等待共享任务默认 200 毫秒，操作完成后新请求可见，Redis 已确认更新未丢失的保证范围。
- 本项目没有需要拆为大范围 expand–contract 的机械重构；第一张任务以内收敛地升级现有缓存抽象和调用方，并保持已有跳转回归可验证。

## 已确认任务

### 01：有效短链接通过版本化缓存保持正确跳转

**Blocked by:** None (can start immediately)

**What it delivers:** 有效短链接继续通过 Redis 加速并返回正确的 302；缓存过期、条目丢失或被替换后，旧查询不能无条件恢复旧缓存。为后续拒绝结果、创建协调和请求合并提供相同的版本协议。

**验收范围：**

- 新缓存格式与读取结果能表达 miss、无业务结果占位和可跳转快照，并留出三类拒绝结果的协议表达；占位不能返回 404。
- 版本初始化、条件回填和版本更换具备原子语义；版本与结果在同一个有限 TTL 条目中，条目丢失后旧回填失败，新初始化不复用旧版本。
- 永久正值保持 5 分钟配置上限，写入时向下抖动 0%～10%；限时正值不超过业务剩余有效时长，命中不续期，应用保持精确过期判断。
- 302、Location、no-store、大小写、非法格式以及 Redis 读写失败时的原有跳转降级通过回归验证。
- 真实 Redis 验证序列化、有限 TTL、占位语义与旧版本条件回填失败；以 SQL 次数证明有效 hit 不查 MySQL。
- 创建后的完成与部分完成响应在 02 中接入；本任务聚焦已有跳转读链路和可被业务流程调用的协调能力。

### 02：不存在短码复用 404，创建完成后立即可访问

**Blocked by:** 01 — 有效短链接通过版本化缓存保持正确跳转

**What it delivers:** 重复访问同一个不存在短码复用 404 缓存；该短码随后创建并完成协调后，新开始的请求可按新映射使用。数据库已经创建但协调未确认时，创建者得到可恢复的部分完成结果。

**验收范围：**

- 成功查询确认为不存在后写入 404 结果，上限默认 30 秒，实际抖动为 27～30 秒；后续命中不查 MySQL，不延长 TTL。
- 新建映射数据库确认提交后更换缓存版本并清除旧结果，协调确认后返回现有 201；可以留下占位，但不预热原始 URL。
- 数据库确认提交后协调失败／超时返回专门 503，携带 shortCode 和“已提交、协调未确认”说明，日志能够按短码定位；数据库失败或提交未确认不冒充该结果。
- 提供受控的内部按短码协调恢复能力，多次执行安全，不重新发号、插入映射或按旧请求重写启用状态。
- 用受控旧查询回填竞态及跨实例场景证明创建完成后新请求不受旧 404 影响，覆盖协调已执行但响应超时后的恢复。
- 通过 HTTP 与真实 MySQL／Redis 验证首次 miss、后续负 hit、创建成功、503 和恢复时映射／发号次数不增加。
- 少量不同无效短码验证新码仍可能查库、条目有限 TTL；数据库查询失败保持 500 且不写 404。

### 03：已过期映射复用 410，保留业务到期边界

**Blocked by:** 01 — 有效短链接通过版本化缓存保持正确跳转

**What it delivers:** 重复访问已过期映射不再反复查询数据库，同时可跳转快照在业务到期当刻仍返回 410，不因缓存寿命而继续跳转。

**验收范围：**

- MySQL 确认为已过期时写入独立 410 结果，上限默认 5 分钟，实际抖动为 270～300 秒；后续命中不查 MySQL。
- 过期结果、不存在结果和可跳转结果明确区分；过期仍优先于禁用，缓存命中不续期。
- 业务到期前、到期当刻和之后由可控时钟验证；正值 TTL 与业务过期时间不混淆。
- 业务过期产生的结果更新也遵守版本条件，不能覆盖变更后或重新初始化的缓存条目。
- 真实 Redis／MySQL 与 HTTP 验证 410 miss／hit、TTL 和负缓存自然到期后的回源。
- 本任务只依赖共同版本协议；404 缓存及创建的 503 恢复交付不是其前置条件。

### 04：已禁用映射复用 403，受控重新启用立即生效

**Blocked by:** 02 — 不存在短码复用 404，创建完成后立即可访问；03 — 已过期映射复用 410，保留业务到期边界

**What it delivers:** 已禁用映射短时间复用 403；维护者数据库提交并完成受控协调后，新开始的请求按当前启用状态判断，已到期映射仍返回 410。

**验收范围：**

- 未过期但已禁用时缓存独立 403 结果，保留业务过期时间，上限默认 15 秒，实际抖动为 13.5～15 秒，命中不续期。
- 403 缓存到业务过期时返回 410；使用 03 的已过期结果与过期判断能力，保持过期优先于禁用。
- SQL 状态维护提交后使用受控版本协调，分别报告数据库变更与操作完成；不新增公开维护 API，不把仅 COMMIT 或仅 DEL 描述为操作完成。
- 复用 02 的按短码协调恢复能力；协调未确认时能够重试，恢复只更新缓存版本及清除结果，不重新设置旧 enabled 值。
- 旧的已禁用查询在重新启用完成后迟到回填被拒绝；多个实例使用同一协议时，新请求不受旧 403 影响。
- HTTP／真实 MySQL／Redis 验证禁用 miss／hit、重新启用后的 302 或自然过期后的 410、协调失败恢复及数据库状态不被恢复步骤覆盖。

### 05：同码同版本请求在实例内合并，等待超时仍可回源

**Blocked by:** 04 — 已禁用映射复用 403，受控重新启用立即生效

**What it delivers:** 对已经具备全部业务结果的跳转流程，正常的一轮同码同版本 miss 在每个实例内共享一次 SQL；不同码并行，等待超时的请求可以继续读取权威数据。

**验收范围：**

- 合并键为短码和版本，每个实例独立持有正在进行的任务，不使用长期本地缓存或跨实例 Redis 锁。
- 无变更、无超时且正常回源时，一轮交叠请求各实例只查一次；可跳转、404、403、410 都适用。不同码可以同时进入数据库查询。
- 新版本请求不能加入旧版本任务；创建／重新启用完成后的新请求不得得到旧任务的 404／403。
- 默认等待 200 毫秒且可配置，超时后重读一次缓存，仍 miss 则独立 SQL；允许重复回源，不无限重新加入任务，也不取消其他请求仍使用的共享任务。
- 各请求使用共享快照时重新判断业务过期，等待期间到期后返回 410，不能沿用较早的 302 或 403。
- 任务成功或失败后清理，数据库失败保持 500 且不产生拒绝缓存，后续请求可以重试。
- 用可控同步点和查询计数证明合并、不同码并行、任务隔离及超时语义；保留至少一项独立实例／进程隔离的验证，明确各实例允许各回源一次。
- 04 已完成三类拒绝结果及重新启用流程，是全结果合并和新旧任务隔离验收的前置条件；其阻塞关系已覆盖 01、02、03。

### 06：Redis 中断与旧数据恢复后保持正确跳转

**Blocked by:** 05 — 同码同版本请求在实例内合并，等待超时仍可回源

**What it delivers:** Redis 临时不可达时访问者仍能按 MySQL 结果跳转或得到正确拒绝原因；维护者在 Redis 重启、切换或恢复旧数据后，通过受控清理恢复按需缓存，明确即时可见的保证边界。

**验收范围：**

- 在版本协议及请求合并已经接入后，真实 Redis 断连／超时仍正确回源，不能把缓存异常误报成 404。
- 版本无法确认时不加入可能跨越变更的旧任务，不无条件回填；读取路径回填失败不改变已读到的 MySQL 结果，变更协调失败则不能报告操作完成。
- 损坏／未知结构、错误时间及错误结果类型按既定 miss／降级语义处理，不产生错误跳转或错误拒绝。
- 提供并验证受控的停用旧缓存、清理旧格式或旧数据、恢复按需加载流程，覆盖旧结果与旧版本整体恢复的场景。
- 文档与验证明确：同一 Redis 主实例、已确认协调未丢失是保证前提；自动故障切换或恢复旧快照不能未经清理就宣称保持即时可见。
- 保留短 Redis 超时与可定位日志，说明 TTL 抖动、实例内合并、整体不可用和正常命中热点的各自边界；不引入新的监控平台、限流、熔断、预热或高可用组件。
- 本任务的故障验证包含 05 的版本不明与任务共享风险，因此依赖 05；其他任务的常规业务与并发测试已经随各自交付完成。
