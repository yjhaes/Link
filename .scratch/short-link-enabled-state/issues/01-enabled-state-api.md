# 01: 内部短链接启用/禁用接口与有限缓存同步重试

**What to build:** 按已确认的 [规格](../spec.md) 增加单条短链接映射的状态维护接口，拒绝过期和重复操作，确认数据库提交后有限重试缓存同步，并准确报告部分完成结果。

## Acceptance criteria

- [ ] 新增 PUT /api/links/{code}/enabled，接受必填 enabled 布尔字段，成功返回 200、shortCode 与本次提交的 enabled 状态。
- [ ] 非法/不存在短码返回 404 LINK_NOT_FOUND，无效请求体返回 400 INVALID_REQUEST；所有拒绝均不改变映射。
- [ ] 已过期映射禁止任何状态操作，过期优先于重复状态，返回 410 LINK_EXPIRED。
- [ ] 重复启用/禁用分别返回 409 LINK_ALREADY_ENABLED、LINK_ALREADY_DISABLED，不执行数据库更新或缓存协调。
- [ ] 状态更新只改变 enabled，保留短码、原始 URL、创建和过期时间，不重新发号或创建映射。
- [ ] 同一码的状态判断和更新具有数据库并发保护，按数据库提交顺序生效；等待后重新检查状态和有效期，不依赖进程内锁维持跨实例保证。
- [ ] 数据库状态只更新一次，确认提交后才同步缓存；数据库失败不重试更新、不同步缓存、不使用“数据库已更新”的 503。
- [ ] 复用既有版本轮换、结果清除及条件回填协议；只有数据库提交且缓存同步确认后才返回成功，不以 DEL 或 TTL 代替完成条件。
- [ ] 缓存同步最多尝试三次，两次重试前分别等待 50、100 毫秒；任何一次确认成功立即停止，耗尽后停止自动尝试。
- [ ] 缓存重试仅同步缓存，不重新写入 enabled；延迟重试、Redis 已执行但响应丢失及重试期间自然过期均不会覆盖后续状态或改变有效期。
- [ ] 耗尽返回专用 503 错误、明确的部分完成 message 和 shortCode，并保留已提交状态及按短码定位的日志。
- [ ] 503 后重复提交同一状态仍按当前状态返回 409；保留仅重试缓存协调的内部恢复方法，不增加恢复 HTTP 接口或后台补偿。
- [ ] 更新接口和维护说明；明确响应 enabled 为本次提交结果，有限重试不保证长故障或重启后自行恢复，完成后的新访问可见性遵守既有缓存故障边界。
- [ ] 复用现有 HTTP、服务及真实 MySQL/Redis 测试边界，覆盖规格的请求/响应、到期当刻、重复拒绝、部分完成、重试序列、提交顺序、迟到旧回填与独立实例可见性。
- [ ] 既有创建、302/404/410/403 跳转语义及 no-store 保持；新增状态成功和错误响应同样为 no-store。
- [ ] 仅实现后端接口，不新增页面、鉴权模型、表、后台任务或创建重试策略。
