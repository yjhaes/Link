# 阶段 1：短链接系统 MVP

## Problem Statement

我希望做一个可用于 Java 后端实习简历的短链接项目，并能亲自解释其核心设计。第一阶段需要完成从原始 URL 创建短链接、持久化短链接映射、访问短码时 302 跳转，以及对不存在、已过期、已禁用链接的准确处理。范围应足够小，让实现和测试都围绕这些核心行为展开。

## Solution

匿名创建者提交一个合法的 HTTP 或 HTTPS 原始 URL，可选填写有效分钟数；系统每次生成一个新的、可直接使用的短链接。访问者打开短链接时，系统按当前映射状态返回原始 URL 的 302 跳转，或明确的错误状态。创建者无需注册。维护者可通过数据库操作禁用或重新启用映射；过期规则始终独立生效。

## User Stories

1. 作为匿名创建者，我希望不注册账号就能创建短链接，以便专注于核心功能。
2. 作为匿名创建者，我希望提交完整的 HTTP URL，以便缩短普通网页地址。
3. 作为匿名创建者，我希望提交完整的 HTTPS URL，以便缩短安全网页地址。
4. 作为匿名创建者，我希望本地和内网地址也能作为目标，以便验证和使用内部页面。
5. 作为匿名创建者，我希望 URL 的路径、查询参数和片段保持原样，以便跳转到我提交的目标。
6. 作为匿名创建者，我希望格式错误或缺少主机的 URL 被拒绝，以便不会得到无法正确跳转的短链接。
7. 作为匿名创建者，我希望包含用户名或密码的 URL 被拒绝，以便不会无意保存凭据。
8. 作为匿名创建者，我希望首尾带空白、直接包含非 ASCII 字符或超过长度上限的输入被明确拒绝，以便知道第一版接受的 URI 边界。
9. 作为匿名创建者，我希望省略有效时长时创建永久有效的短链接，以便不必总填写期限。
10. 作为匿名创建者，我希望显式传入空有效时长时也创建永久有效的短链接，以便两种可选字段写法含义一致。
11. 作为匿名创建者，我希望按分钟指定有效时长，以便控制短链接何时过期。
12. 作为匿名创建者，我希望 0、负数、非整数和超过上限的有效时长被拒绝，以便获得可预测的期限。
13. 作为匿名创建者，我希望同一原始 URL 每创建一次都获得新的短码，以便各条映射有独立期限和启用状态。
14. 作为匿名创建者，我希望创建成功时获得完整短链接、短码和到期时刻，以便立即使用并了解期限。
15. 作为匿名创建者，我希望短码偶然重复时系统尝试生成新短码，以便一次偶然碰撞不导致创建失败。
16. 作为匿名创建者，我希望连续碰撞无法创建时收到明确错误，以便知道本次没有产生新映射。
17. 作为访问者，我希望有效且启用的短链接返回 302 跳转，以便打开原始 URL。
18. 作为访问者，我希望目标网站暂时不可用时映射仍按自身状态判断，以便目标站故障不被误判成短链接失效。
19. 作为访问者，我希望不存在或格式错误的短码返回 404，以便知道没有可访问的映射。
20. 作为访问者，我希望恰好到达过期时刻的短链接返回 410，以便期限边界明确。
21. 作为访问者，我希望被禁用但尚未过期的短链接返回 403，以便区分人工禁用和过期。
22. 作为访问者，我希望同时过期且禁用的链接报告过期，以便获知重新启用也无法恢复跳转。
23. 作为访问者，我希望每次访问都根据当前状态判断，以便禁用或重新启用后不会沿用旧的跳转结果。
24. 作为维护者，我希望能通过数据库操作禁用映射，以便在没有用户系统和管理接口的 MVP 中停止跳转。
25. 作为维护者，我希望能通过数据库操作重新启用未过期映射，以便恢复原短码的跳转。
26. 作为维护者，我希望过期或禁用映射保留且短码不复用，以便旧短链接的含义稳定。
27. 作为 API 调用者，我希望参数错误和链接状态错误都有稳定错误码与可读消息，以便识别失败原因。
28. 作为 API 调用者，我希望意外数据库错误不会在响应中暴露内部细节，以便接口行为清晰且安全。

## Implementation Decisions

- 使用 Java 17、Spring Boot、MySQL、MyBatis-Plus 和 Maven。第一阶段只需要短链接映射这一张表及创建、跳转两个公开接口。
- 每次创建产生独立映射；不按原始 URL 去重或复用短码。同一原始 URL 可以对应多条映射。
- 表字段为：`short_code CHAR(8) NOT NULL PRIMARY KEY`、`original_url VARCHAR(4096) NOT NULL`、`created_at DATETIME(3) NOT NULL`、`expires_at DATETIME(3) NULL`、`enabled BOOLEAN NOT NULL DEFAULT TRUE`。短码列使用区分大小写的 `utf8mb4_bin` 排序规则。短码主键已保证唯一，不增加同列唯一索引；原始 URL、到期时刻和启用状态也不另建索引。主键取舍遵循已有 ADR。
- `created_at` 与 `expires_at` 按 UTC 保存和读取，并统一时间精度。创建时只读取一次当前时刻。`expires_at` 为空表示永久有效；否则为创建时刻加有效分钟数。访问时当前时刻大于或等于 `expires_at` 即视为已过期，不写入单独的过期状态。
- 短码固定 8 位，仅含小写英文字母和数字，由 Java 17 的 `SecureRandom` 生成。直接尝试插入；只有短码主键冲突时才重新生成，首次加最多三次重试，共最多四次尝试。其他数据库错误不重试。
- 创建接口为 `POST /api/links`，接收 JSON 字段 `originalUrl` 与可选整数 `validMinutes`。后者省略或为 `null` 均表示永久有效；填写时只接受 1 至 5,256,000 分钟。上限按 3,650 天换算，不代表日历意义上的十年。
- 原始 URL 必须为长度不超过 4,096 字符、格式合法且带主机的绝对 HTTP/HTTPS URI。允许本地和内网目标；拒绝用户信息、空白、控制字符、无效编码、不合法端口和直接输入的非 ASCII 字符。合法 URI 的路径、查询参数及片段原样保存；不探测 DNS 或目标网站可达性。
- 创建成功返回 `201 Created`，JSON 正文包含 `shortCode`、完整 `shortUrl` 和 `expiresAt`；永久有效时 `expiresAt` 为 `null`，否则用 UTC 时间表示。`shortUrl` 根据配置的短链接地址前缀构造，响应的 `Location` 指向它。
- 跳转接口为 `GET /s/{code}`。先验证短码是 8 位小写字母或数字；格式错误或不存在返回 `404 LINK_NOT_FOUND`，已过期返回 `410 LINK_EXPIRED`，未过期但已禁用返回 `403 LINK_DISABLED`，其余返回 `302` 并在 `Location` 放入原始 URL。若同时过期且禁用，先返回已过期。
- 跳转和失败响应带 `Cache-Control: no-store`。服务端只返回 302，不主动访问或跟随目标网站。
- 错误正文统一为含 `code`、`message` 的 JSON。创建请求的 JSON 错误与参数校验错误统一返回 `400 INVALID_REQUEST`；四次短码碰撞返回 `500 SHORT_CODE_GENERATION_FAILED`；其他意外错误返回 `500 INTERNAL_ERROR`，不暴露内部异常文本。使用集中异常处理保持两个接口一致。
- `enabled` 只表示人工启用状态。第一阶段通过数据库操作禁用或重新启用，不提供相关 API。重新启用不能绕过过期判断。过期或禁用记录不自动删除，短码不复用。

## Testing Decisions

- 测试以可观察行为为主：给定请求、映射状态和时间，验证 HTTP 状态、响应字段、`Location`、错误码及持久化结果；避免仅复述私有方法实现。
- 主要测试入口是公开 HTTP 接口，使用真实 MySQL 验证完整创建和跳转流程。针对不便由 HTTP 稳定触发的时间边界与随机碰撞，增加少量业务单元测试，使用可控制的时钟和短码候选值。另用针对真实 MySQL 的持久化测试确认主键、空到期时间、UTC 读写和短码精确比较。这里延续了已确认的“业务单元、HTTP 接口、真实 MySQL”三层测试取舍。
- 创建测试覆盖永久与限时链接、1 分钟和最大值、相同 URL 重复创建、成功的 `201` 与完整短链接，以及无效 URL、凭据、空白、非 ASCII、长度边界、无效分钟数和错误 JSON 的 `400`。
- 碰撞测试覆盖首次冲突后成功、四次冲突后 `500` 且无新映射，以及非短码冲突的数据库错误不触发重试。
- 跳转测试覆盖 `302 Location` 与 `no-store`、格式错误及不存在的 `404`、过期边界的 `410`、禁用的 `403`、同时过期且禁用优先返回 `410`、重新启用未过期链接恢复 `302` 和过期链接无法因重新启用而恢复。
- 当前仓库尚无应用代码或既有测试，因此没有可沿用的测试实现先例。

## Out of Scope

- 用户系统、链接所有者、“我的链接”列表、查询详情接口、自定义短码，以及通过 API 禁用或重新启用。
- 自动删除过期或禁用记录、短码复用、目标网站可达性检查和服务端跟随目标跳转。
- Redis、RabbitMQ、访问统计、高并发、限流、部署，以及这些方向带来的扩展设计。
