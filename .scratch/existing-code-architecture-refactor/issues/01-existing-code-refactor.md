# 01: 重构现有短链接用例职责，保持行为与协议

**What to build:** 按已讨论并收紧的范围，拆分创建与跳转职责、归位 MySQL 错误分类、集中已有缓存配置并确认后精简无调用操作。保留单 Maven 模块、现有 HTTP 契约、短码规则、事务提交和 Redis 一致性语义。

**Spec:** [现有短链接代码职责重构](../spec.md)

## Acceptance criteria

- [ ] 创建与跳转由清晰的完整用例 module 分别承担；没有永久保留纯转发旧 façade，没有引入跨包循环。
- [ ] MySQL 特有错误分类集中到持久化 implementation；只有短码主键冲突重新发号重试一次，其他约束或数据库失败不被误判。
- [ ] 发号与映射分别提交；真实 Spring 代理场景证明映射确认提交后才协调缓存，协调确认后才报告完成。
- [ ] 原 HTTP 输入、响应、状态、Location、校验范围、短码大小写与过期优先级保持不变；已提交但协调未确认的专门 503 与内部恢复保持有效。
- [ ] Redis v2 协议、有限 TTL、抖动、命中不续期、版本条件回填、旧任务隔离、Redis 故障回源与数据库失败语义保持不变。
- [ ] 每实例按短码和版本合并加载；等待预算、超时后处理、任务清理及逐请求到期复查保持不变。
- [ ] 已有缓存配置集中绑定和校验，原配置键、默认值与环境变量覆盖保持兼容；关闭缓存不会误报创建或恢复完成。
- [ ] 核对无生产调用缓存操作的维护用途；无用途则精简，有真实用途则记录保留理由；不增加透传仓储或重复模型。
- [ ] 架构、配置默认值和内部维护说明与实现一致；可选类名整理没有改变外部契约。
- [ ] 依据规格保留并完成现有行为、并发、事务和真实 MySQL／Redis 验收，记录未运行环境及原因，不以跳过测试宣称完成。
- [ ] 未实现统计、RabbitMQ、消费幂等、限流、outbox、Maven 多模块或数据库迁移，未预建相关空包或配置。
