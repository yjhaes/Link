Status: ready-for-agent

## Problem Statement

项目已经实现短链接创建、MySQL 持久化、短码生成、跳转、Redis 版本化缓存、实例内请求合并和缓存协调恢复。Maven 目录、Spring Boot 根包位置以及 HTTP、业务编排、持久化的基本分工合理，当前没有依据要求推倒目录骨架或立即改成多模块。

主要阅读困难集中在 `ShortLinkService`：创建校验、发号与插入重试、MySQL 特有错误判断、数据库提交后的缓存协调、内部恢复、跳转判定、缓存回退及并发加载协议都在同一类中。修改创建规则时需要避开跳转并发状态，修改跳转时又需要理解创建和事务完成语义。

缓存配置散落在实现构造器，多个重载构造器增加装配与测试的阅读成本。缓存 interface 还包含无生产调用的操作。部分默认配置与文档说明不一致，进一步增加维护者判断实际行为的成本。

用户希望现有项目清晰、内聚、便于讲解和继续开发。访问统计、RabbitMQ、重复消费幂等和限流尚未实现，不能把这些未来能力当作当前代码问题，也不能在本次重构中提前实现或预建空目录。

## Solution

在现有单 Maven module 和包布局中，按完整用例拆分创建与跳转职责，将 MySQL 错误分类集中到持久化 implementation，整理已有缓存配置并精简确认无用途的公开操作。

创建 module 隐藏建立短链接映射所需的校验、发号、冲突重试和完成状态；跳转 module 隐藏缓存回退、版本隔离、加载合并、等待预算和业务到期复查。保留现有发号与缓存 seam，不为每个类新增 Java interface，不保留纯转发 façade。

重构以保持已实现行为为前提：HTTP 契约、短码规则、数据库提交顺序、缓存 v2 协议、跳转拒绝结果和内部维护恢复语义不变。通过现有入口与真实依赖验收验证行为，并同步架构、运行和维护说明。

### 结构与职责

- 保留单 Maven module、当前应用根包及 HTTP、业务编排、缓存、持久化、短码功能包。启动类继续位于根包；不增加仅用于未来功能的目录。
- 从 `ShortLinkService` 分离创建 module 和跳转解析 module，建议使用 `ShortLinkCreationService` 与 `RedirectService` 作为职责名。最终命名应清晰且统一；验收不依赖某个必须采用的类名。
- 创建 module 集中 URL 与有效时长校验、时间计算、发号编码、短码冲突重试、数据库确认保存后的缓存协调和创建结果。内部协调恢复可留在这一写入完成职责中；不为当前少量共享语义强制增加独立协调 module。
- 跳转 module 集中短码格式校验、缓存读取与回退、数据库加载、结果判定、版本条件回填、实例内任务合并、等待超时及每次请求使用结果时的到期复查。
- HTTP adapter 直接调用相应完整用例；不永久保留仅转发到两个 module 的旧 `ShortLinkService` façade。内部维护说明和测试装配同步迁移，不要求保留旧的具体类名。
- 请求合并状态属于每个跳转实例的 implementation。优先保留内部实现；只有能集中真实复杂性时才进一步提取内部加载 module。
- 保留发号 interface、确定性短码编码 module、缓存 interface 和可控 Clock seam。不为编码器或每个业务类补 Java interface，不增加通用 Repository 或 MyBatis-Plus 全套 CRUD 业务抽象。
- 保留 HTTP 请求/响应、创建用例结果和数据库实体的分工。当前允许业务编排使用 Mapper 和实体，不额外复制一套仅换名称的领域模型。
- Redis adapter 继续封装 Lua、版本、序列化、坏值处理和 TTL。可以改善内部阅读顺序，不按私有函数数量机械拆分为多个公开 module。
- 依赖继续从 HTTP 指向业务编排，再指向缓存、持久化和短码约定；不引入循环，缓存与持久化不反向调用 HTTP 或业务编排。

### 持久化知识与提交语义

- 将 MySQL 1062 和 PRIMARY 错误文本分类集中到持久化 implementation。创建 module 处理分类后的短码主键冲突；数据库特有解析不继续散落在业务编排中。
- 错误分类不得将其他唯一约束冲突、一般数据库错误或未确认插入归入短码重试。短码主键冲突总共最多插入映射两次，每次重新发号；第二次仍冲突则创建失败。
- 不新增仅转发 Mapper 操作的存储 façade。若提取保存 adapter，它必须集中真实错误分类或已确认提交语义，不能只改变调用层数。
- 遵守 ADR-0002：短码仍作为映射主键，精确区分大小写；采用现有固定有界双射与 4 至 8 位编码规则；发号和映射分别提交，允许未使用的发号 ID，不回收或复用。
- 保持当前 Spring 管理的创建和恢复入口挂起调用者事务的效果。拆类后验证真实代理调用，不能依靠同类自调用注解来假定事务已生效。
- 只有映射确认提交后才轮换缓存版本，且只有协调确认后才报告创建完成。数据库未确认提交时维持普通服务失败，不对外声称映射已经保存。
- MySQL 与 Redis 不构成原子事务。协调失败不能描述为数据库回滚，也不能通过一个跨发号、映射与缓存的大事务改写现有失败语义。
- 本次不修改数据库表结构、索引、建表或启动初始化行为，也不引入数据库迁移工具。

### 对外行为与缓存协议

- 创建继续使用现有 POST 入口，输入仍为原始 URL 和可空的有效分钟数；成功维持 201、现有字段与 Location。有效分钟范围、URL 长度、字符与 URI 校验不变。
- 数据库创建已提交而协调未确认继续返回带短码的专门 503 和不缓存响应；保留可定位短码的日志。网络响应丢失后重复 POST 仍可建立另一条独立映射，不增加创建请求幂等。
- 跳转继续使用现有 GET 入口。非法格式或不存在返回 404，已过期返回 410，未过期但已禁用返回 403，可跳转返回 302 与原始 URL 的 Location。跳转及错误响应保持不缓存。
- 业务到期判定采用现有 UTC 时间与毫秒精度语义，到期当刻即为已过期；过期优先于禁用。静态网页及已有 JSON 字段不需要随内部重构改变。
- 遵守 ADR-0004 的 v2 缓存协议，保留缓存格式、命名空间、版本标识和结果类型，不混淆 miss、占位、不存在、已过期与已禁用。
- 所有业务结果回填和由到期产生的结果更新都按版本原子校验。条目丢失后旧回填失败，新初始化不复用旧版本；创建或维护完成后的新请求不复用旧版本加载任务。
- 每实例按“短码＋当前版本”共享正在进行的加载，不使用 JVM 全局任务表、跨实例回源锁或长期本地结果缓存。不同短码、不同版本可并行；成功或失败后清理任务。
- 等待共享任务的默认预算仍为 200ms。超时后仅重读一次缓存，仍 miss 则独立回源；允许额外 SQL，不无限重入任务，不取消其他请求使用的共享任务。
- 每个请求使用共享快照时重新检查业务到期，不能将加载者较早得到的 302 或 403 直接作为等待者的最终结果。
- Redis 版本无法确认时独立查 MySQL，不加入可能过时的任务，不无条件回填。数据库查询失败继续为 500，不建立跳转拒绝结果缓存；缓存回填失败不改变已读到的数据库业务结果。
- 恢复协调仍是受信任内部入口，不新增公开维护操作。确认原短码映射存在后，仅轮换缓存版本并清除结果；重复恢复不重新发号、插入映射或覆盖后续状态。
- 受控维护继续区分“数据库变更已提交”与“缓存协调已确认”。Redis 恢复旧快照或切换后的清理要求及一致性保证范围不变。

### 已有配置、缓存 interface 与文档

- 将已有跳转缓存 TTL、三类拒绝结果 TTL、缓存开关和等待预算集中绑定并校验，可采用 `RedirectCacheProperties` 与 `@ConfigurationProperties`。不新增统计、AMQP 或限流配置。
- 保留现有配置键、环境变量覆盖方式和默认值：正值与已过期上限各 5 分钟，不存在上限 30 秒，已禁用上限 15 秒，加载等待预算 200ms，缓存默认启用。
- TTL 必须能表示为正的毫秒时长，等待预算必须为正且可表示为纳秒；明确处理绑定失败、空值或转换溢出。配置无效时启动失败，不在请求过程中悄悄采用不同默认值。
- 业务结果写入继续向下抖动 0%～10%，命中不续期；限时正值 TTL 不超过业务剩余有效时长。版本占位维持有限 TTL，不因为配置整理变成永久条目。
- 缓存关闭时跳转独立回源；创建仍可能已提交但协调无法确认，恢复不能报告完成。配置关闭不能变成“无需协调即成功”。
- 当前 `deleteIfVersion` 无生产调用。实施时核对受信任维护说明及调用范围；确认无用途后移除此操作、对应实现和仅为它存在的测试桩。若存在实际用途则保留并说明，不新增用途来维持一个浅操作。
- README、架构和维护说明随实现同步，尤其是默认数据库密码说明与实际配置不一致的问题；保留配置现状，仅纠正文档，不借机更改连接行为。
- 启动类、请求/响应类的统一命名属于低优先级可选整理；不作为必须扩大修改范围的验收项。若选择改名，应一次同步引用和文档，保持 HTTP 契约。

## Testing Decisions

- 主验收 seam 优先使用现有 HTTP 创建与跳转入口，验证请求、响应、状态、Location、错误结果和部分完成恢复的可观察行为。内部维护恢复通过现有受信任应用入口验收，不新增测试用 HTTP 入口。
- 补充现有创建和跳转用例入口测试、发号与缓存 seam 测试，以及真实 MySQL／Redis adapter 集成测试。只在 HTTP 难以稳定控制并发或故障顺序时下降到既有内部 seam，不为这次重构增加测试专用公开 interface。
- 好测试关注行为与已承诺的资源语义：缓存命中不查 SQL、正常一轮同码同版本 miss 合并为一次 SQL 都是有效验收目标。类名、构造器数量、私有方法、纯转发调用链和任意行数上限不是验收目标。
- 沿用 `ShortLinkApiTest` 的 HTTP 契约场景，`ShortLinkServiceTest` 的创建、冲突与恢复场景，`RedirectLoadCoalescingTest` 的受控并发场景，`PermutedShortCodeEncoderTest` 的固定规则验收，以及 `RedisRedirectCacheTest` 与 `RedisRedirectIntegrationTest` 的配置和真实协议验收。测试装配随职责变化迁移，不为了保留旧类名增加兼容 façade。
- 创建验收覆盖永久/限时输入与错误范围、相同原始 URL 的独立映射、固定短码规则、仅主键冲突重试一次、其他唯一约束不重试，以及发号空洞。
- 用真实事务验证创建已确认提交后才协调缓存；保留调用者事务回滚不会撤销已提交创建的场景，以及未确认保存不报告 503 部分完成的场景。直接 new 出业务对象的测试不能替代 Spring 事务代理验收。
- 协调验收覆盖 503 带已保存短码、Redis 已执行但确认丢失、重复恢复、恢复不增加发号或映射、恢复不覆盖后续禁用状态，以及创建/重新启用完成后的新请求隔离旧拒绝结果。
- 跳转验收覆盖 hit/miss、格式拒绝、大小写隔离、404/410/403 区分、过期优先、等待期间到期、数据库失败不建拒绝缓存、坏值/未知格式忽略和 Redis 故障回源。
- 并发验收使用闩锁等同步点、可控时钟和 SQL 计数，覆盖同码合并、不同码并行、新旧版本隔离、共享失败清理、超时重读/独立回源、任务不被等待者取消。避免用长 sleep 或所有响应相同推断合并成功。
- 保留独立 Spring 应用上下文各自持有任务并共享真实 MySQL／Redis的验收，明确每实例允许各回源一次；不将其描述为独立进程压测或全局唯一回源。
- 配置和缓存协议验收覆盖原默认值、环境变量覆盖、非法时长绑定失败、关闭语义、抖动端点、实际 TTL、占位有限寿命、命中不续期与旧版本条件回填拒绝。精简 interface 时继续保留有关缓存关闭和版本保护的行为验收。
- 可以按创建协调、跳转缓存、请求合并和恢复分组较大的测试类，复用真实依赖装配；不以测试文件拆分数量作为目标，不通过跳过既有场景换取通过。
- 验收证据包含测试结果、未运行环境及原因、无循环依赖检查和文档一致性检查。当前只承诺正确性与既有查询减少，不承诺重构提高 QPS。

## Out of Scope

- 实现访问统计、PV/UV、RabbitMQ 发布或消费、消息去重、死信、outbox、创建请求幂等、限流、熔断或数据库回源预算。
- 为上述未来功能创建空包、空 Maven module、预留配置或提前定义消息契约。
- 改变短码生成机制、字符表、参数、主键、大小写语义、ID 提交规则或增加生产数据清理。
- 改变 Redis v2 格式、版本协调算法、一致性保证范围或等待超时行为；引入跨实例回源锁、长期本地缓存、Bloom Filter、自动预热或自动故障切换。
- 数据库表结构或索引改动、Flyway/Liquibase 迁移、数据库初始化方式调整。
- 新增公开启用、禁用、删除或恢复入口；改变现有 HTTP 路径、字段、校验范围、状态码或网页用户流程。
- 强制改根包、启动类、所有 DTO 命名，新增通用 common/utils 包、透传 Repository 或重复领域实体。
- 升级 Java、Spring Boot、MyBatis-Plus 或其他依赖，以及没有实测依据的性能承诺。
- 本次规格发布直接执行重构、修改生产代码或修改测试实现。

## Further Notes

- 本规格依据收紧后的架构审查与当前实现形成；用户已经明确部分后续功能尚未实现。当前四项候选只针对既有代码，未来扩展不转化为本次执行要求。
- 领域术语沿用现有 single-context 文档：原始 URL、短码、短链接映射、有效时长、已过期、已禁用、不存在与跳转拒绝结果。此次不新增领域概念，不重开 ADR-0002 与 ADR-0004 的既有决策。
- module 表示有 interface 与 implementation 的职责集合，不等同于 Maven module；interface 是 caller 需要了解的规则，不等同于 Java interface 关键字。重构应增加 depth、提高 locality，并使已有 seam 与 adapter 继续提供 leverage。
- 采用 deletion test 评估新抽取：删除后复杂性若重新散到 caller，module 有语义价值；删除后只少一层转发则应取消该抽取。不以更多包、类或抽象作为完成标志。
- 推荐实施顺序为先建立行为基线，再拆创建与跳转，随后集中数据库错误分类、已有配置及无调用操作，最后同步说明并完成回归。
- 用户已确认测试 seam：“符合，按现有入口验收”。采用现有 HTTP 主验收并补充已有用例、真实事务与 MySQL／Redis 测试，不新增测试专用公开入口。
- 状态 ready-for-agent 表示规格与任务可用于后续执行，不表示重构已开始或测试已通过。本次只发布本地 Markdown 规格和任务。
