# 01: 现有启用/禁用操作受统一管理令牌保护

**What to build:** 内部管理者通过 X-Internal-Token 使用现有启用/禁用接口；未配置或未通过令牌校验时不进入状态业务。有权限的操作继续遵守已接受的状态及缓存协调规则。交付同一可供后续统计接口复用的管理访问控制边界。

## Acceptance criteria

- [ ] 管理令牌由独立环境配置提供，至少 32 字节随机秘密，无默认值，不放 URL、Cookie、页面存储、响应或日志；采用精确安全比较，不 trim。
- [ ] 未配置令牌时现有状态 PUT 返回 404；配置后缺失、错误或重复头返回 401 INTERNAL_UNAUTHORIZED。
- [ ] 鉴权先于参数/请求体解析与业务调用，拒绝时没有 MySQL/Redis 业务调用；验证无效请求体不能绕过鉴权顺序。
- [ ] 有效令牌下保留成功 200、不存在 404、重复状态 409、过期 410、数据库行锁和提交顺序。
- [ ] 保留提交后最多三次缓存协调及 50ms/100ms 间隔，耗尽时返回已有带短码的 503；不重新写库，不声称已回滚。
- [ ] 成功与错误响应均 no-store；创建和普通跳转保留原公开访问契约，不新增恢复 HTTP API 或用户体系。
- [ ] 更新既有状态测试的有效令牌配置，并通过 HTTP、数据库状态和后续跳转核对原规则；未授权验收独立验证业务无副作用。
- [ ] 后续统计接口可以复用同一令牌边界，不在本任务增加尚未完成的统计接口或日志表。
