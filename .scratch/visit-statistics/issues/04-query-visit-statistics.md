# 04: 管理者查询日期范围 PV/UV 与日趋势

**What to build:** 内部管理者通过受令牌保护的聚合接口，得到单短码日期范围的已记录 PV、整体去重 UV 和逐日趋势；已有禁用/过期映射可以查询历史，缺数据与查询失败有不同的明确结果。建立明细及清理验收可复用的日期窗口和查询边界。

**依赖说明：** 01 — 现有启用/禁用操作受统一管理令牌保护；02 — 合法跳转同步记录匿名访客访问日志

## Acceptance criteria

- [ ] 交付 GET /api/internal/links/{code}/stats，GET 及其隐式 HEAD 复用统一令牌；鉴权先于校验与业务，全部成功/错误响应 no-store。
- [ ] from/to 均缺省默认最近7天，两端包含；使用上海日界线与 UTC 左闭右开范围，严格限制最近30日（含今天），不依赖物理清理已完成。
- [ ] 单端、重复、非法、逆序、未来及超窗日期返回400；已鉴权后短码非法/不存在404，已有禁用或过期映射仍可查询。
- [ ] 查询存在性及日志读取使用统计池；查询准入容量1，忙503 STATS_BUSY、明确超时503 STATS_QUERY_TIMEOUT、其他数据库错误500，不重试或返回伪造零值。
- [ ] 响应字段完整：范围 PV/UV、逐日 date/pv/uv/isOngoing、时区、anonymous-cookie、best-effort、采集状态、身份版本、生成时间及查询范围。
- [ ] 范围 UV 对版本与访客摘要组合整体去重，不累加日UV；同访客三天访问，各日UV=1而范围UV=1；两个短码即使同URL也不混算。
- [ ] 汇总、趋势和身份版本在同一短只读 REPEATABLE READ 普通一致性快照中取得，不对映射加锁，生成时间不声称精确提交截止。
- [ ] 无已记录访问的有效日期补零，当天标记进行中；停采仍读取历史并标记 collectionEnabled=false，多身份版本显式呈现拆分边界，不承诺历史补采。
- [ ] HTTP 与真实 MySQL 验证默认/窗口边界、UTC转换、跨日去重、大小写及已有状态查询；受控在多次读取间并发插入/删除，证明同一响应快照一致。
- [ ] 现有真实缓存与状态协调回归保持；本任务不实现分页明细或日志调度清理。
