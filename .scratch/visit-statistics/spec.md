# 阶段 5：同步访问统计

## Problem Statement

短链接服务已经支持创建、302 跳转、业务过期、启用/禁用以及 Redis 跳转缓存，但内部管理者无法知道短链接映射被访问了多少次、有多少匿名访客、访问发生在哪一天，也无法查看经过最小化处理的访问信息。

访问统计必须有明确的 PV、UV 和时间口径，否则缓存命中、请求合并、Cookie 缺失、跨日去重与故障处理容易产生难以解释的数字。访问记录还包含可能用于关联访客的信息，不能仅凭公开短码开放查询，也不能让同步统计故障阻断正常跳转或耗尽核心数据库连接。

本阶段需要一个能够真正解释和验证的同步版本。它用于观察已记录的流量，接受故障和繁忙时漏记，不承诺每次访问可靠入账、真实人数、固定吞吐或严格的 HTTP 总耗时上限。

## Solution

在每个 GET 请求通过最终逐请求有效性检查、作出正常跳转决定后，生成独立访问事件并同步尽力保存到 MySQL 访问日志。PV 从已保存的事件数量取得，UV 按匿名 Cookie 身份在单条短链接映射及查询范围内去重；UTC 发生时间按 Asia/Shanghai 分为统计日。每个请求独立统计，包括缓存命中以及共享一次映射加载的多个请求。

匿名访客 Cookie 固定保留 30 天，不续期；缺失或非法时生成新标识并立即参与本次 UV，不回退到 IP。日志保存按短码隔离的访客摘要、脱敏连接对端 IP 网段、限长 User-Agent 和 Referer host，不保存原始 Cookie、完整 IP 或完整 Referer。统计查询严格覆盖最近 30 个上海自然日，在线日志按窗口尽力清理，不提供终身累计。

内部管理者通过受统一请求头令牌保护的 API 查询日期范围汇总、日趋势及分页访问明细。现有启用/禁用接口使用同一保护规则，同时保留已有状态校验、并发提交与缓存协调语义。第一版不新增用户、链接所有者或页面。

统计使用独立小连接池和立即返回的并发准入。没有容量、写入失败或提交结果不确定时允许漏记并记录指标，已经确定的正常跳转继续返回 302。Redis 保持现有跳转缓存职责，本阶段不增加 Redis 统计 Counter/HyperLogLog，也不引入 RabbitMQ 或异步访问采集。

## User Stories

1. 作为短链接访问者，我希望访问有效短链接时继续获得原有 302 和目标地址，以便正常访问原始 URL。
2. 作为短链接访问者，我希望统计写入失败时仍能跳转，以便流量观察功能不会阻断主要服务。
3. 作为短链接访问者，我希望统计容量不足时直接跳过记录，以便请求不会排队等待统计资源。
4. 作为内部管理者，我希望每个正常 GET 跳转决定对应一次已记录 PV，以便访问次数有清楚的采集口径。
5. 作为内部管理者，我希望刷新和客户端再次 GET 分别增加 PV，以便独立请求不会被误当作重复处理事件。
6. 作为内部管理者，我希望 HEAD、创建、查询、状态维护及跳转拒绝请求不进入访问日志，以便统计只反映选定的访问事件。
7. 作为内部管理者，我希望缓存命中的访问也被记录，以便启用缓存后访问量不会漏算。
8. 作为内部管理者，我希望多个请求共享映射加载时仍各自记录，以便数据库加载次数不会被当作 PV。

## Implementation Decisions

### 统计口径与时间

- PV 是单条短链接映射及指定时间范围内符合口径的已记录访问事件数量。只有 GET 通过短码和最终逐请求有效性校验、作出正常 302 决定时生成事件。刷新与客户端再次 GET 是新的事件。
- 作出决定前的非法短码、404/403/410、数据库读取错误以及 HEAD、创建、统计查询和状态维护不产生访问事件，不设置访客 Cookie。第一版包含符合口径的爬虫和预览器 GET，不进行真人识别。
- UV 对同一短码及范围内的匿名 Cookie 身份去重。范围 UV 直接在整个范围去重，不累加每日 UV。两个短码即使指向同一原始 URL 也分别统计，短码保持大小写敏感。
- 跳转决定不证明响应实际发送成功或目标网页被打开。客户端断连、响应发送失败以及故障漏记不能被描述为完整、真实的用户访问。
- 跳转用例向 HTTP 入口返回原始 URL 以及在最终逐请求检查时冻结的决定时刻。用同一个时刻判断到期并计算事件发生时间，入口不得事后重新读取 Clock 推测决定时间。
- 每个使用共享加载结果的请求各自执行最终检查并形成时间，冻结时刻不放进共享加载结果。等待加载时已经到期仍拒绝；决定之后在统计等待期间到期或禁用不推翻在途 302。
- 发生时间保存为 UTC 毫秒，stat_date 按同一时刻的 Asia/Shanghai 自然日计算。跨午夜写入仍归入发生日，不用插入完成时间重新分桶。继续使用项目已有 UTC 时钟与数据库时间约定。

### 模块与边界

- 统计事件、记录、存储、查询、清理和资源控制集中于 stats 功能。HTTP 控制、管理令牌校验以及原始请求信息提取位于 Web 边界；现有跳转用例负责映射解析与有效性判定。
- 逐请求正常跳转入口调用窄的统计记录边界；当前实现同步写 MySQL。统计不能放在缓存回填、共享数据库加载或缓存 adapter 内。
- 访问事件是独立、已经规范化的值对象，包含事件 ID、短码、冻结的发生时间、统计日、访客摘要及版本和脱敏元数据，不复用 HTTP DTO、映射实体或缓存状态对象。
- 原始 Cookie、完整 IP、完整 Referer、令牌和 HttpServletRequest 不进入事件或持久化边界。可以在生成事件前调用不依赖 Servlet 的规范化函数。
- 统计日志只作独立同步提交，不加入创建、映射维护或缓存协调事务，也不重新查询映射来决定是否记录已经通过检查的事件。
- 保留现有短码编码、创建流程、跳转缓存 v2 协议、TTL、版本条件回填、实例内加载合并及 Redis 受控恢复规则。

### 匿名访客 Cookie 与摘要

- Cookie 名为 sl_visitor；标识为 128 位安全随机值，使用规范的无填充 Base64URL，长度 22 字符。验证其解码为 16 字节且重新编码一致，不将格式校验当作认证或防机器人能力。
- 合法单值 Cookie 沿用原标识。缺失、非法或同名多值无法明确时生成新标识，本次立即参与 UV；不回退到 IP 或 IP＋User-Agent。
- Cookie 固定保留 30 天，命中不续期，host-only、不设置 Domain、Path=/s、HttpOnly、SameSite=Lax；HTTPS 部署开启 Secure。统计关闭以及非访问事件请求不生成 Cookie。
- 接受拒绝/清除 Cookie、浏览器提前丢失标识和首次并发导致的 UV 偏高；服务端无法在首次无 Cookie 请求时判断浏览器是否会保存响应 Cookie。不同设备、浏览器或重新生成标识可以代表不同匿名访客。
- 访客摘要使用 HMAC-SHA-256，独立密钥至少 32 个随机字节，没有默认共享秘密。输入采用无歧义、有版本的编码，包括用途标识、密钥版本、大小写敏感短码和 Cookie 随机字节。
- 所有实例使用相同规则、密钥及版本。同一版本对应固定密钥；保留期内不常规轮换。紧急更换密钥必须更换版本，明确说明同一 Cookie 跨版本可能被计为多个身份，不声称 UV 连续无变化。
- 随机值或摘要生成失败时跳过本次统计并记录失败，正常跳转继续；不写入一个供所有失败请求共享的默认访客摘要。

### 元数据与隐私

- 仅采集连接对端地址，明确停用对外部 Forwarded/X-Forwarded-For 的自动信任；不实现可信代理客户端 IP 解析。部署反向代理时，此地址可能是代理，不能称为真实访客 IP。
- IPv4 保留前 24 位、IPv6 保留前 48 位，其余位清零；IPv4-mapped IPv6 先规范化为 IPv4。保存规范化网段及前缀长度，去掉 zone 等本机信息，不做 DNS、地域识别或外部网络请求。无法解析置空。
- UA 清理控制字符后按完整 Unicode 字符限长至 512，缺失允许为空，不截断出非法字符。
- Referer 只保留合法 HTTP/HTTPS 来源的规范化 host，处理大小写、合法 IDN 和末尾点后限长至 253；丢弃用户信息、端口、路径、查询和 fragment。相对引用、about:blank、无 host、非法或超限 host 置空。
- UA/Referer 是不可信输入，缺失或畸形不阻断正常跳转；Referer 为空不证明一定为直接访问。
- 不保存原始 URL 副本、完整 IP、原始 Cookie、完整 Referer、整组请求头、Authorization、地理位置或 UA 解析结果。脱敏和摘要减少采集范围，不代表完全匿名。
- 错误日志只记录事件 ID、受控错误类别和阶段等定位信息，不包含秘密、Cookie 或原始请求元数据。在线表及备份的访问、统计 Cookie 用途和保留期需要在部署说明中明确。

### MySQL 日志模型

新增 short_link_visit_log，只追加访问事件；窗口外日志可以批量删除。应用在进入存储前生成 UUID 事件 ID，数据库自增行 ID 只服务于存储与分页。

| 字段 | 类型与约束 | 含义 |
| --- | --- | --- |
| id | BIGINT，自增主键，非空 | 数据库行标识和分页排序依据 |
| event_id | BINARY(16)，非空，唯一 | 应用生成的访问事件 UUID |
| short_code | VARCHAR(8)，utf8mb4_bin，非空 | 大小写敏感的映射逻辑引用 |
| occurred_at | DATETIME(3)，非空，UTC | 最终检查通过时冻结的发生时间 |
| stat_date | DATE，非空 | 发生时间对应的上海统计日 |
| visitor_hash | BINARY(32)，非空 | 按短码隔离的 HMAC 访客摘要 |
| visitor_key_version | SMALLINT UNSIGNED，非空 | 摘要密钥版本 |
| peer_ip_network | VARCHAR(49)，可空 | 脱敏对端 IP 网段及前缀长度 |
| user_agent | VARCHAR(512)，utf8mb4，可空 | 清理且限长的 UA |
| referer_host | VARCHAR(253)，可空 | 合法规范化的来源 host |

- 独立 event_id 唯一约束；聚合索引包含 short_code、stat_date、visitor_key_version、visitor_hash；明细索引包含 short_code、occurred_at、id；清理索引包含 stat_date、id。
- 使用自增行 ID 作聚簇主键，事件 UUID 使用独立唯一索引。各二级索引有写入与存储成本，实施时用实际查询及 EXPLAIN 验证，不承诺任意范围 UV 为常数时间查询。
- 同一事件的内部重放沿用 event_id，不能新增行或增加 PV；客户端再次 GET 使用新事件 ID。只识别事件唯一约束对应的重复，不把其他数据库异常吞成正常去重。
- short_code 不加外键，由合法访问事件边界控制逻辑引用，避免日志插入额外校验并锁住映射。当前不存在删除映射 API；未来删除必须重新设计日志处理，不能假定级联删除。
- 不在映射表增加 PV/UV，不新增每日汇总表、UV 去重表、recorded_at 或拒绝请求审计字段。新增日志表不重建或清理现有映射与发号数据，初始化归属明确。

### 同步写入、资源和故障

- MySQL 日志为唯一统计权威。Redis Counter 适合原子递增 PV，HyperLogLog 适合近似基数，但本版不维护这些数据、不做统计双写或 Redis 查询缓存。
- 日志同步写入发生在已确定的跳转决定之后。没有容量立即跳过，有容量在请求线程上执行单条日志提交；不建立访问队列、不增加异步线程池、不在请求内重试。
- 统计 DataSource 指向同一 MySQL，最多 4 个连接；初始写入、查询、清理准入容量分别为 2、1、1。立即尝试准入，成功或异常后均释放容量。
- 明确核心 DataSource、MyBatis、JDBC 模板、发号及核心事务管理器的归属；统计 writer/query/cleanup 显式使用专用连接和事务。增加同类型 bean 不得接管核心自动配置、核心状态事务或重复执行数据库初始化。
- 统计池 minimumIdle=0，采用不因连接预检失败导致启动失败的初始化策略，实际操作按超时取得连接。它不增加新的统计网络启动硬依赖；核心已有数据库初始化依赖仍存在。

| 统计专用设置 | 起始值 | 限制阶段 |
| --- | --- | --- |
| Hikari connectionTimeout | 1000ms | 取连接等待 |
| Hikari validationTimeout | 500ms | 连接验证 |
| Connector/J connectTimeout | 500ms | 网络建连 |
| Connector/J socketTimeout | 1000ms | socket 网络操作 |
| JDBC Statement 超时 | 1 秒 | 写入及查询语句执行 |
| 统计会话 InnoDB 行锁等待 | 1 秒 | 行锁等待，仅作用于统计连接 |

- 这些是可配置起点，不是压测结果或 HTTP 总墙钟上限。Hikari 最低等待值和各超时阶段的限制必须尊重，语句取消和事务 timeout 不能证明写入未发生。
- 忙时记录 dropped；写入失败或提交结果不确定时记录受控失败，正常跳转仍返回 302、Location 和 no-store。不盲目重试，不改写映射或缓存，不宣称确定回滚。
- 统计不能使创建或状态维护事务跟随日志失败回滚。独立池减少连接竞争，不代表共享 MySQL 硬件、HTTP 线程或进程得到完全故障隔离。
- 观察事件尝试、确认保存、丢弃、失败/不确定、耗时、查询超时、池占用和清理积压；短码、IP、访客标识不作无限增长的指标标签。不为本规格新增监控平台或公开诊断接口。

### 聚合查询 API

- GET /api/internal/links/{code}/stats，使用统一管理令牌保护。
- from、to 都不传时默认本次上海日期及前 6 日；显式日期使用 YYYY-MM-DD，两端包含。只传一端、重复参数、非法日期、逆序、未来日期或超出最近 30 日窗口返回 400 INVALID_REQUEST，不静默截断。
- 每次请求固定窗口：本次上海日期及前 29 日。按上海日界线转换为 UTC 左闭右开时刻范围，日期和发生时刻一致。
- 已鉴权后，非法或不存在短码返回 404 LINK_NOT_FOUND。已有禁用/过期映射仍可查询。映射存在性查询及日志读取使用统计专用连接，不占用核心映射连接池。
- 响应包含 shortCode、from、to、timeZone、pv、uv、uvBasis、collectionPolicy、collectionEnabled、identityVersions、generatedAt，以及每日 date、pv、uv、isOngoing。
- timeZone 为 Asia/Shanghai，uvBasis 为 anonymous-cookie，collectionPolicy 为 best-effort。collectionEnabled 表示当前是否采集；identityVersions 列出范围内观察到的版本，多版本明确身份拆分风险。generatedAt 是响应生成时间，不宣称精确数据库提交截止时刻。
- 范围 PV 为匹配日志行数，范围 UV 对整个范围内 visitor_key_version 与 visitor_hash 的组合去重；每天单独计算 PV/UV。有效日期没有记录时补零，当天 isOngoing，零值不证明实际没有访问或采集完整。
- 聚合使用显式短只读 REPEATABLE READ 事务中的普通一致性读取；汇总、趋势和身份版本来自同一快照，不用行锁。第一版没有故障期间或统计启用前的历史补采能力。

### 访问明细 API

- GET /api/internal/links/{code}/visits，使用同一令牌、短码及日期校验规则。
- limit 默认 20，合法范围 1 至 100；非整数、重复或超限返回 400 INVALID_REQUEST。
- 响应表达短码及最终日期范围、items、nextCursor、hasMore。每项只含 occurredAt、peerIpNetwork、userAgent、refererHost，不返回 Cookie、visitor_hash 或密钥。
- 按 occurred_at 与 id 倒序排序，取 limit+1 判断 hasMore，不使用大 OFFSET，不计算总页数。
- 游标包含最后排序位置，绑定短码、日期范围和格式版本；严格校验解码、结构和查询范围。游标不是访问凭证，不替代令牌。
- 续页沿用首次确定的范围，解析出的范围须与游标一致。游标原行已删除时按排序位置继续，不要求该行存在。
- 跨页不承诺固定快照，新写入、迟到记录和清理可能改变可见数据；返回首页可重新查询。窗口移动导致原范围移出保留窗口时返回 400，不维持过期历史访问。

### 管理令牌和现有状态接口

- X-Internal-Token 保护两种统计 GET、其隐式 HEAD 和现有 PUT /api/links/{code}/enabled；不新增第二个状态接口。
- 管理令牌由 SHORT_LINK_INTERNAL_TOKEN 环境配置提供，使用至少 32 字节随机秘密，不提供默认值，与 HMAC 密钥分开。部署经 HTTPS 传递。
- 未配置管理令牌时受保护接口返回 404，不执行业务；配置后缺失、错误或重复头返回 401 INTERNAL_UNAUTHORIZED。
- 鉴权在参数/请求体解析和业务调用之前完成，拒绝时不读取短码、不访问数据库或 Redis。精确安全比较，不 trim，不接受 URL/Cookie 替代，不在页面存储、响应或日志中保留令牌。
- 受保护接口所有成功和错误响应均 no-store。创建与普通跳转的公开访问范围保持原有契约，不新增用户、所有者或角色授权。
- 有效令牌下，现有状态接口继续返回 200、404、重复操作 409、过期操作 410；MySQL 行锁判断/更新和提交顺序规则保持。
- 状态提交后 Redis 协调最多尝试三次，重试前分别等待 50ms、100ms；只重试协调，协调确认才返回完成。耗尽返回已有带短码的 503 部分完成响应，不声称数据库回滚。
- 重复状态 PUT 不能用于恢复协调；原有受信任内部方法仅协调当前已提交状态，不重写 enabled。本规格不新增恢复 HTTP API，不改变创建协调策略。

### 查询错误与采集开关

| 条件 | HTTP / 结果 |
| --- | --- |
| 未配置管理令牌 | 404，受保护接口关闭 |
| 缺失、错误或重复令牌头 | 401 INTERNAL_UNAUTHORIZED，先于解析/业务 |
| 已鉴权但短码非法或不存在 | 404 LINK_NOT_FOUND |
| 日期、limit、cursor 非法或超窗 | 400 INVALID_REQUEST |
| 查询没有准入容量 | 503 STATS_BUSY |
| 统计查询明确超时 | 503 STATS_QUERY_TIMEOUT |
| 其他统计数据库错误 | 500 INTERNAL_ERROR |

- 查询失败不伪装为零访问，不在请求内重试，不泄露数据库或请求原文。
- 采集可独立开关，默认关闭；关闭时不生成事件或 Cookie，不写日志，不要求 HMAC 密钥。已鉴权的查询仍能读历史，并明确 collectionEnabled=false；状态管理的令牌保护继续生效。
- 启用采集必须提供有效独立 HMAC 密钥和版本；显式非法配置启动失败。运行期依赖失败按跳转优先处理。
- 采集开关不承担 Redis 恢复职责，不关闭跳转缓存，也不停止旧日志清理。

### 日志清理

- 30 个统计日是严格查询窗口和在线清理目标，物理删除为受资源及故障影响的尽力维护，不能承诺故障期间所有超窗日志已经删除。
- 应用启动后及每天上海时间 00:10 清理窗口外记录，每批最多 1000 行、按 stat_date/id 索引、每批独立提交。
- 单轮预算 30 秒，有积压时每 15 分钟继续一轮。无容量或失败时不在该轮反复重试，记录最旧日志日期和积压，下一轮继续。
- 单条阻塞 SQL 受统计专用超时约束；轮次预算不宣称能强制中断任意阻塞。多个实例重复清理须安全，不新增分布式锁或任务表，不依赖内存游标保存进度。
- 关闭采集仍清理旧日志；停机期间不声称能清理，恢复启动后按过期条件追赶。清理是维护任务，不是异步访问采集或统计补偿。
- 即使清理延迟，查询也先限制有效窗口。删除明细后无法恢复旧 PV/UV，日 UV 数值不能恢复任意跨日并集。
- 在线删除不代表备份或 binlog 同时删除，实际部署须明确其访问和保留规则；本规格不自动管理数据库备份。

### 后续异步化的铺垫

- 事件边界保留稳定 event_id、short_code、冻结发生时间、已计算统计日、身份摘要及版本和脱敏元数据；未来处理不重新解析浏览器请求或按处理时刻分桶。
- 统计记录边界当前为同步 MySQL 写入，未来可以替换提交方式；业务口径、查询模型和跳转缓存加载职责继续分开。
- event_id 唯一约束为重复处理提供基础；未来新增汇总时，去重与统计变更须在同一数据库事务内完成。
- 本版不实现消息投递或消费，也不因此保证可靠产生事件、可靠投递、端到端恰好一次或无限期去重。
- 30 日清理会删除事件去重记录，未来允许晚到或长时间重放时须重新设计幂等保留期、过期事件处理及修复。

## Testing Decisions

### 测试边界和已有先例

- 用户已经在完整设计确认中接受这些测试边界。本次直接合成规格，不重新访谈，也不编写或运行实现测试。
- 以 HTTP 请求、响应、数据库持久化结果和后续跳转为最高验收边界。尽量从这一边界验证完整行为，不测试私有方法或逐句镜像实现。
- 复用 ShortLinkApiTest 的 MockMvc、真实 MySQL、可控 Clock 和测试缓存；复用 RedisRedirectIntegrationTest 的真实 MySQL 8.4、Redis 7.2、独立应用实例及受控故障。
- 复用 RedirectLoadCoalescingTest、ShortLinkUseCasesTest、ShortLinkStateServiceTest 的时钟、mapper/cache seam 和闩锁同步点，验证等待、状态与错误传播。
- 原有状态测试配置有效管理令牌，保留既有业务验收；新增独立的未授权测试，证明鉴权失败时没有核心业务副作用。
- 如现有边界不足，只在统计事件记录/存储这一用例边界增加最小替换能力，用来控制写入故障、已保存后确认丢失、事件重放和容量。不扩散大量透传接口，不增加生产测试 HTTP 入口。
- 并发用闩锁控制先后，时间用可控 Clock。容量限制和超时是已确认行为，可观察其外部结果和资源恢复；不凭响应相同、随机抽样或长 sleep 宣称并发正确。
- 少量真实 MySQL 故障验证超时实际生效，使用有余量的有界等待；mock 抛异常只验证失败语义，不证明耗时上限。真实故障注入仅限隔离测试环境。

### 验收场景

| 场景 | 应验证的结果 |
| --- | --- |
| 同 Cookie 多次 GET | 独立事件 ID、PV 增加、UV 为 1；客户端重试不是事件内部重放 |
| 排除请求 | 非法/拒绝/决定前错误、HEAD、创建、查询、状态维护无访问日志和访客 Cookie |
| 机器人 GET | 符合口径即记录，不能声称真人过滤 |
| hit、miss、共享加载 | 都逐请求记录；容量足够时两个共享加载请求有两条日志，映射只加载一次 |
| 正常跳转回归 | 302、Location、no-store，以及原有 404/403/410 与缓存版本语义保持 |
| 访客 Cookie | 首次/非法/同名多值重建、合法复用、不续期、固定格式和安全属性；HEAD 不生成 |
| Cookie 偏差 | 无回传和首次并发可产生多身份，明确偏高，不回退到 IP |
| 短码维度 | 相同 Cookie 在两码下不同摘要、分别计数；同 URL 不合并、大小写不混算 |
| 跨日 UV | 每日 UV 各为1，三日范围 UV 为1，PV为全部匹配日志 |
| 冻结发生时间 | 用例传递检查时刻，入口不重读钟；跨午夜提交仍是原统计日，各等待者独立定时 |
| 到期与禁用交叠 | 决定前到期拒绝，决定后统计等待中的变化不改在途302；新请求依既有规则处理 |
| 身份版本 | 同配置跨实例去重、不同短码隔离、紧急新版本明确身份拆分 |
| IP 来源与脱敏 | IPv4/IPv6/映射地址/无效地址；伪造代理头不改变对端来源，无完整 IP 落库 |
| UA 与 Referer | 缺失、非法、控制字符、超长、Unicode、IDN；只保留规范化字段，元数据错误不中断跳转 |
| 真 MySQL 模型 | UTC 毫秒、统计日、字段边界、短码大小写及 event_id 唯一约束 |
| 同事件重放 | 日志至多一条、PV不重复；其他数据库错误不被当作正常去重 |
| 写入失败与未知提交 | 失败仍302、不重试；先保存后报错仍仅一事件，不断言超时必定未执行 |
| 容量与释放 | 占满写入容量后其他跳转立即跳过并增加 dropped；失败和成功后许可恢复 |
| 数据源归属 | 日志/查询/清理用统计池，核心 mapper/JDBC/发号/状态事务及初始化归属保持 |
| 真实超时 | 隔离环境核验断连、锁等待或网络延迟下各配置生效，结果不伪造为成功 |
| 聚合一致快照 | 汇总与趋势之间并发写入/删除，同一只读 RR 请求仍看到一致结果，普通读取不锁映射 |
| 日期与零值 | 默认7天、30日首尾、两端包含、上海UTC转换、补零、当天进行中及 best-effort 说明 |
| 查询已有状态 | 已禁用/过期仍可查，真实不存在404；查询错误不能伪装零值 |
| 参数拒绝 | 单端/重复/非法/逆序/未来/超窗日期及非法 limit/cursor 返回400 |
| 游标行为 | 同毫秒稳定分页、limit+1、范围绑定、原行删除、新写/清理/窗口移动，无固定快照承诺 |
| 令牌保护 | 未配404，缺失/错/重复401；GET/HEAD/状态PUT均保护，先于解析，无DB/Redis业务调用 |
| 现有状态回归 | 合法令牌下重复409、过期410、并发提交、三次协调、已提交503及内部恢复保持 |
| 缓存与隐私 | 所有查询/管理响应no-store，不向响应或错误日志泄露令牌、Cookie、摘要或完整请求元数据 |
| 清理生命周期 | 启动/每日/积压、批量/预算/失败/无容量、多实例重复、关闭采集继续及停机后追赶 |
| 开关与启动 | 默认停采无日志/Cookie，不要求HMAC；历史可查并标记停采；统计预检失败不新增网络启动硬依赖 |
| 配置校验 | 启用所需密钥/版本及显式非法超时失败，不使用默认生产秘密；令牌与HMAC分别配置 |

这些测试证明口径、外部行为、资源归属和持久化正确性，不代替吞吐压测，不承诺任意规模下的延迟与故障隔离。

## Further Notes

- 本规格依据已经接受的 ADR-0006 和领域术语，由当前访谈直接合成；用户已确认 Q1至Q9、Q11至Q17，包括测试边界与完整设计。状态为 ready-for-agent，不代表实现已经认领或完成。
- 基线为 main 的 c069f33，已经包含启用/禁用实现。继承 ADR-0004 的缓存协议与恢复边界，以及 ADR-0005 的状态操作规则；新增鉴权增补原先内部接口不实现鉴权的范围。
- 测试验收特别区分“缓存命中不查映射”与“统计仍写 MySQL”。PV/UV 都是已保存事件上的结果；Cookie 偏差、停采、繁忙丢弃和提交不确定必须保持可解释。
- 30日查询窗口不是故障期间的物理删除硬期限；日志清理也会清除事件去重依据，未来消息化需要重新决定晚到、幂等保留和数据修复。
- Counter/HyperLogLog 的适用性已经讨论：前者不能自动去重超时重试，后者只能估计集合基数并需合并范围，不能将每日 UV 相加。本规格选择单一日志来源，避免同步双写与修复复杂度。
- 本轮发布一个完整规格，不拆分或创建实施任务，不变更已接受 ADR 的技术选择，不引入 RabbitMQ。
