## What to build

访问者可以通过 4 至 8 位、区分大小写的 Base62 短码打开已保存的短链接，仍按映射状态得到原始 URL 的跳转或现有错误响应。这一任务先扩展持久化与读取路径，让当前 8 位小写随机短码继续可用，为后续切换创建机制做好准备。

## Acceptance criteria

- [x] 短链接映射首次保存时短码非空，长度可为 4 至 8 位，数据库主键按大小写精确区分；开发和测试环境的现有表能够真正更新到该结构。
- [x] 已保存的 4 位、7 位、8 位且包含大写字母的短码可通过现有跳转路径访问；短码只改变大小写时不会误跳转到另一条映射。
- [x] 3 位、9 位或含非 Base62 字符的短码继续返回稳定的不存在响应，失败响应不缓存。
- [x] 现有 8 位小写短码的创建、跳转、过期和禁用行为保持可用；沿用 MockMvc 与真实 MySQL 的接口集成测试验证上述可观察行为。

## Answer

- 将短码列改为 `VARCHAR(8) NOT NULL` 并保留 `utf8mb4_bin`；`schema.sql` 在建表后执行 `ALTER TABLE`，可把已有 `CHAR(8)` 表升级到新结构。
- 跳转校验接受 4 至 8 位大小写字母和数字，创建生成器仍生成原有 8 位小写短码。
- MockMvc 与真实 MySQL 全量测试通过：26 项，无失败；另有旧表迁移回归测试。
