# 短链接与异步访问统计架构优化规格

日期：2026-10-03  
评估基线：`e9dd03d4980f624c4d0f04cf97b815ae8f3124aa`  
范围：将已讨论的完整架构优化方案落实为行为兼容的结构重构。规格发布不表示生产实现已经开始或完成。

## Problem Statement

项目已经实现短链接创建、跳转、启禁用、版本化 Redis 缓存、RabbitMQ 异步访问采集、访问日志持久化、统计查询和保留维护。现有单 Maven module 以及核心用例封装总体合理，但新增统计能力让目录与运行职责逐渐失去清晰对应。

访问统计把身份、元数据、发布、消费、查询、清理和配置集中在同一包。发布 recorder 同时知道拓扑初始化、消费者启动和应用关闭，网络资源所有权又分散在配置、框架生命周期 adapter 和消费者关闭实现中。维护者理解一次启动或停机需要跨多个位置追踪隐含顺序，修改发布流程容易影响消费者生命周期。

MySQL 访问日志实现同时暴露 best-effort 同步采集和持久化确认两种不同承诺，旧同步入口目前主要由测试直接调用。统计配置还装配核心数据库连接池，名称与实际资源归属不一致。架构导航仍保留同步阶段和未来消息能力的描述，增加定位与讲解成本。

用户希望获得清晰、可读、高内聚且耦合受控的项目骨架，并保持已经实现的业务规则、故障语义和设施隔离。目标是降低理解和变更成本，不是增加抽象数量或依据类长度拆分实现。

## Solution

在现有单 Maven module 内渐进重构，按真实职责组织统计内部 module，集中 MQ 应用生命周期决策，收窄 MySQL 持久化职责，明确核心与统计数据库装配归属，并整理 HTTP 管理、统计和错误表示。

创建、跳转、启禁用、缓存协议、消费决定、查询快照与清理轮次继续保持完整封装。调用者通过已有 interface 获得行为，而不需要学习线程、连接销毁、SQL 分类和内部状态。只收敛确认没有独立价值的同步适配与便利入口，不增加透传 façade 或通用 repository。

通过用户已确认的现有 HTTP 行为和真实 Spring 启动/关闭入口验收，辅以现有缓存、发号、持久化、消息和可控时钟 seam 注入故障。先验证职责变化，再逐组搬迁目录、测试和文档，保持每一步可审阅、可回退。

## User Stories

1. 作为项目维护者，我希望目录能对应已落地能力，以便根据一次变更的目的快速找到实现和测试。
2. 作为项目维护者，我希望访问统计的采集、消息、持久化、查询、清理和配置分别内聚，以便不必在一个平铺目录中辨认所有技术角色。
3. 作为项目维护者，我希望已有核心创建、跳转和启禁用用例保持完整封装，以便修改规则时不追踪大量透传类。
4. 作为项目维护者，我希望 MQ 应用生命周期有明确的决策位置，以便知道每个连接和线程由谁启动、恢复和终止。
5. 作为项目维护者，我希望发布 recorder 专注事件交接和发布，以便发布变更不携带消费者启停知识。
6. 作为项目维护者，我希望网络清理由后台 adapter 执行，以便集中生命周期职责后仍不会阻塞应用关闭调用线程。
7. 作为系统维护者，我希望 broker 不可用时核心应用仍能启动和处理请求，以便统计依赖故障不成为核心启动的新硬依赖。
8. 作为系统维护者，我希望拓扑声明和消费者启动在核心 ready 后后台执行，以便它们的重试不拖住 HTTP 启动。
9. 作为系统维护者，我希望静态非法配置仍明确启动失败，以便结构重构不会掩盖配置错误。
10. 作为系统维护者，我希望消费者启动尊重独立消费意图，以便人工暂停不会被发布恢复隐式撤销。
11. 作为系统维护者，我希望发布与消费继续使用独立连接，以便发布故障和恢复不直接中断消费。
12. 作为系统维护者，我希望只恢复发布连接，以便历史消息消费、查询和清理不随发布错误重新启动。
13. 作为短链接访问者，我希望访问统计交接不等待 MQ 或统计 JDBC，以便统计故障时仍能按现有规则跳转。
14. 作为系统维护者，我希望缓冲满、事件等待过久和未确认容量不足仍按现有分类处理，以便资源保持有界且观察口径稳定。
15. 作为系统维护者，我希望一个发布尝试的终态与许可释放分别只发生一次，以便确认、超时、返回和关闭竞态不重复计数或释放资源。
16. 作为系统维护者，我希望阻塞发送时独立观察仍能判定 unknown，以便错误观察不依赖发送线程返回。
17. 作为系统维护者，我希望迟到 ACK 不覆盖已结算终态，以便故障后的观察结果可信。
18. 作为系统维护者，我希望连接 reset 完成且原发送者返回后才重新开放发布，以便恢复不制造重叠发送。
19. 作为系统维护者，我希望应用关闭先停止新交接，以便清空待发队列后不会又接收新事件。
20. 作为系统维护者，我希望迟到启动任务不能在关停期间重新启动消费者，以便终止意图保持有效。
21. 作为系统维护者，我希望 MQ 关停的等待共用有限预算，以便多个 worker 的等待不会累加成长期阻塞。
22. 作为系统维护者，我希望重复关闭通知不重复清理、释放许可或创建线程，以便不同 Spring 生命周期通知可以安全重叠。
23. 作为系统维护者，我希望未确认发布继续明确为不确定，以便关停不被误解为消息一定未送达。
24. 作为系统维护者，我希望消费者未 ACK 的消息仍可重投且依靠 eventId 去重，以便已保存但确认丢失的事件不会重复计入访问日志。
25. 作为项目维护者，我希望 MySQL 实现只承担持久化确认，以便调用者不会误用同步采集入口令 HTTP 再次等待 JDBC。
26. 作为消费逻辑维护者，我希望只有 eventId 唯一键重复被视为已记录，以便其他约束错误不会被错误 ACK。
27. 作为消费逻辑维护者，我希望保存确认丢失和保存后清理失败继续区分，以便重试与确认依据保持正确。
28. 作为消费逻辑维护者，我希望暂时失败最多执行三次而永久错误立即拒绝，以便有限重试与最终不 requeue 语义稳定。
29. 作为统计维护者，我希望每次消费重试前重新检查保留窗口，以便跨日或人工重放不会写入超窗日志。
30. 作为统计维护者，我希望访问事件的发生时刻与统计日保持冻结，以便迟到、重试和映射状态变化不修改历史口径。
31. 作为项目维护者，我希望核心数据库装配与统计池装配职责明确，以便统计目录和扫描调整不会意外改变核心资源归属。
32. 作为系统维护者，我希望核心 Mapper、发号、JdbcTemplate 和事务仍使用核心池，以便统计容量不会抢占核心用例资源。
33. 作为系统维护者，我希望统计写入、查询和清理继续使用专用池和独立准入，以便失败后资源能够释放且没有无界等待。

35. 作为系统维护者，我希望统计池保持懒初始化且建表初始化只执行一次，以便资源装配重构不引入新启动连接要求。
36. 作为内部管理者，我希望管理保护继续先于参数和请求体解析，以便未获准请求不会执行用例或泄露解析行为。
37. 作为内部管理者，我希望 GET、隐式 HEAD 和启禁用请求保持相同保护规则，以便搬包不形成绕过入口。
38. 作为项目维护者，我希望管理标记与统一错误表示具有单向依赖，以便细分 HTTP 目录不会引入包循环。
39. 作为短链接创建者，我希望原始 URL 与有效时长校验、独立映射创建和返回字段保持，以便已有客户端继续工作。
40. 作为短链接创建者，我希望数据库提交后缓存协调未确认仍返回携带短码的部分完成结果，以便可以恢复原映射而非重复创建。
41. 作为短链接访问者，我希望不存在、已过期和已禁用继续有不同跳转拒绝结果，以便准确理解不能跳转的原因。
42. 作为短链接访问者，我希望到期检查继续优先于禁用检查且逐请求执行，以便缓存和共享加载不会延长业务有效期。
43. 作为系统维护者，我希望版本条件回填与同码同版本共享加载保持，以便新请求不会使用迟到旧结果。
44. 作为内部管理者，我希望重复状态请求仍拒绝且状态更新只执行一次，以便启禁用语义不会被协调重试改变。
45. 作为系统维护者，我希望状态提交后的三次协调与仅重试协调的恢复语义保持，以便内部目录变化不修改事务完成承诺。
46. 作为短链接访问者，我希望成功 GET 在缓存命中和未命中时都逐请求产生访问事件，以便共享数据库加载不会合并访问计数。
47. 作为统计维护者，我希望 HEAD、跳转拒绝结果和管理查询不采集事件或新增访客 Cookie，以便 PV 口径保持。
48. 作为匿名访客，我希望 Cookie 身份和最小化元数据规则保持，以便重构不增加原始标识或请求信息的暴露。
49. 作为统计查询者，我希望 PV、UV 和日趋势继续依据已记录访问事件，以便消息积压不会被误报为已发生访问的完整统计。
50. 作为统计查询者，我希望跨日 UV 对整个范围去重，以便结果不被每日 UV 相加放大。
51. 作为统计查询者，我希望映射存在性、汇总、趋势与身份版本来自同一读取快照，以便一次响应内部一致。
52. 作为统计查询者，我希望明细游标继续绑定短码和日期范围，以便翻页不混入其他映射或不合法范围。
53. 作为统计查询者，我希望繁忙、超时和数据库错误保持明确失败，以便故障不会伪装成零访问。
54. 作为统计维护者，我希望上海统计日与最近 30 日窗口在采集、消费、查询和清理中一致，以便时区和保留语义不因分包漂移。
55. 作为系统维护者，我希望日志清理保持批量独立提交、轮次预算和失败后追赶，以便维护仍可恢复且不占用无限资源。
56. 作为系统维护者，我希望关闭新事件采集后历史消费、查询和清理继续，以便采集开关不被当成所有统计功能的总开关。
57. 作为系统维护者，我希望交接、发布尝试、消费和持久化观察继续区分，以便重试不被误记为新访问。
58. 作为系统维护者，我希望受控错误日志继续隐藏消息体、Cookie、摘要、令牌和驱动细节，以便结构调整不重新引入框架日志泄露。
59. 作为测试维护者，我希望测试通过现有最高行为 seam 验证，以便重构内部结构时有价值的验收继续存在。
60. 作为测试维护者，我希望同包测试跟随实现迁移且手工 Spring 装配包含新运行生命周期，以便测试不会因漏注册而空跑。
61. 作为测试维护者，我希望旧同步入口和跳转便利入口的测试迁到真实承诺，以便测试双路径减少且异常断言不变弱。
62. 作为项目维护者，我希望排版、import、命名与注释清楚表达规则和竞态，以便阅读代码不用先解开压缩语句。
63. 作为项目维护者，我希望辅助实现保持内部可见，以便搬包不会无理由扩大调用者 interface。
64. 作为网页使用者，我希望永久/限时创建、错误反馈、提交状态、结果展示和复制交互保持，以便代码整理不改变使用体验。
65. 作为项目讲解者，我希望架构、运行与测试导航和实际代码一致，以便解释每个 module 的职责、depth、locality 和 leverage。
66. 作为项目维护者，我希望迁移分成独立可验证步骤并支持逆序回退，以便故障定位不被大规模同时搬包掩盖。
67. 作为验收者，我希望通过、失败、未执行和跳过被明确记录，以便静态检查不被当成运行健康或性能证明。

### 结构与职责

- D01：保留单 Maven module、根包启动类、现有 Java 与框架版本，以及核心完整用例。目录整理不引入多模块、微服务或新增框架依赖。
- D02：统计内部按 collection、messaging、persistence、query、retention 和 config 分组，只容纳已有职责和明确新增的运行生命周期。全部现有生产 Java 类型必须具有唯一目标归属，同包测试跟随迁移。
- D03：HTTP 管理保护归 api.management，统计采集和查询表示归 api.stats，统一错误映射与三个错误表示类型共同归 api.error。核心控制器与少量请求响应保持现有位置。先迁错误表示，再迁管理保护，避免根包与管理包互相依赖。
- D04：既有 VisitEvent、VisitRecorder 和 StatsDateRange 继续为统计内共享契约。StatsDateRange 不归查询实现，消费、清理和调度继续共享现有时区与窗口规则。
- D05：保留 service 对 Mapper/Entity 的实现耦合、统计复用现有业务失败类型、HTTP 读取统计配置，以及采集对 VisitWriteObservations.collectionFailed 的窄引用。后者不使用池快照或写入记录方法；不为目录整齐增加透传 interface。
- D06：核心用例不直接依赖 Redis 具体 adapter、RabbitTemplate、listener 或统计写入实现。统计消息、查询与清理之间不形成循环；持久化、缓存与编码不反向依赖 HTTP。检查显式 import、全限定名与装配引用。
- D07：跨包真实调用的契约、结果和注入类型可以公开；辅助解析、框架 adapter、发布状态和可控构造器保持内部可见。搬包不能机械放宽所有类型或方法。

### MQ 运行生命周期

- D08：新增具体 VisitMqRuntime module，统一接收应用 ready、context-close 与 destroy 通知并幂等处理。它接管后台拓扑初始化和消费启动/终止决策；AsyncVisitRecorder 移除 admin、listener、应用事件和拓扑启动线程知识。
- D09：发布 module 继续负责有界本地交接、发送、confirm/return、独立观察与发布恢复。终态结算和许可退休分别只执行一次；必要同步、恢复门和内部状态保持内聚，不拆成互相通知的公开 module。
- D10：核心 ready 后才后台声明拓扑并按独立消费意图启动 listener。broker 不可用不阻塞核心 HTTP 启动，静态非法配置仍失败。关闭采集只阻止新事件与 Cookie，不停止历史消费、查询或清理。
- D11：发布与消费连接保持分离。恢复只处理发布连接，且 reset 完成和原发送者返回两个条件都满足后才重新开放；消费暂停意图不随发布恢复改变。startup、恢复和关闭任务保持在途门控，不周期性积累无界任务。
- D12：关停顺序为取得一次性终止权、停止新交接、终止迟到启动、清理待发与未确认状态、停止发布 worker 并发起发布/消费异步网络终止，再共用约 2 秒的 MQ 等待预算。等待耗尽返回，重复通知不得重新开放或创建替代 worker，中断保留标记。
- D13：网络 reset/destroy 不在 Spring 关闭调用线程同步执行。发布清理与消费者关闭继续由后台 adapter 执行；保留现有销毁保护、非网络框架 stop 和一次性消费者关闭，直到真实 Spring 行为测试证明可以安全简化。
- D14：MQ 等待预算仅约束本 module 的等待，不是整个进程的统一截止。未发进程内事件允许丢失，未确认不等于未送达；未 ACK 消费可能重投，靠 eventId 去重。消息协议、拓扑、容量、TTL 与 policy 均保持现有值。

### 用例与持久化

- D15：MySqlVisitRecorder 重命名为 MySqlVisitPersistence，仅实现 VisitPersistence；删除调用 persist 后吞异常的同步 record 适配。迁移所有直接调用、注入、spy/mock 与默认 Bean 名引用后再移除遗留实现选择；不增加无用途兼容类。
- D16：VisitRecorder 的本地 best-effort 交接与 VisitPersistence 的保存确认是两个真实 seam，分别保留。持久化保持容量 2 的立即准入、独立自动提交、仅 eventId 重复成功、不确定结果分类、确认后清理失败仍成功，以及所有分支释放容量。
- D17：消费保持同步 listener 与 AUTO ACK。已保存、仅 eventId 重复或合法超窗事件才正常返回；暂时、繁忙或不确定失败最多三次，等待 200/500ms，永久错误立即拒绝，最终拒绝不 requeue。每次重试前重查保留窗口，不改写冻结事件或按映射当前状态重判历史访问。
- D18：创建、启禁用、跳转、Redis 协议、消息校验、查询快照与清理轮次保留深度封装。只在测试统一迁移到 decide 后删除 findOriginalUrl 便利入口；不为校验、序列化、重试或计数机械新增通用辅助 module。
- D19：短码继续大小写敏感的 4～8 位 Base62，发号与映射分别提交，仅短码主键冲突重新发号重试一次。提交后缓存协调、带已保存短码的部分完成响应及仅协调恢复语义保持。
- D20：跳转保留不存在、已过期、已禁用的区别和过期优先，版本条件回填、按短码与版本共享加载、等待超时回退，以及各请求使用结果时的到期复查。启禁用保留行锁后判定、重复拒绝、一次更新和提交后三次缓存协调及 50/100ms 等待。

### 配置、查询与观察

- D21：新增 CoreDataSourceConfiguration 接管既有核心 dataSource 定义，保留 @Primary、原 Bean 名与 Hikari 配置绑定；StatsDataSourceConfiguration 仅装配原 statsDataSource 并保留统计配置绑定。核心 Mapper、发号、JdbcTemplate、事务与 SQL 初始化归属不变，初始化只执行一次。
- D22：统计池容量 4、写入/查询/清理准入 2/1/1、minimumIdle=0 和懒初始化保持。取连接/验证 1000/500ms、网络建连/socket 500/1000ms、SQL/行锁等待各 1 秒保持，不改变核心连接超时或事务策略。
- D23：发布缓冲 256、未确认 32、channel 16、获取等待 200ms、本地年龄与确认观察各 5 秒保持；消费 concurrency/prefetch/batch 保持 1/10/1。业务队列与 DLQ 现有数量/体积限额、24 小时 TTL、溢出策略及无自动回流保持，不附带调参。
- D24：统计只以 MySQL 已记录访问事件为依据，上海日期与最近 30 日窗口保持。范围 UV 对整个范围去重；查询的映射存在性、汇总、趋势和身份版本使用同一 REPEATABLE READ 快照，不能为解耦切成不同连接或使用核心 Mapper。
- D25：明细保留按发生时间与行 ID 降序、limit+1 判断后续页、游标绑定短码/范围/版本和严格校验。分页之间不承诺固定快照；响应生成时间不表示消费水位；繁忙、超时与数据库错误不能伪造为零。
- D26：保留 Cookie 身份、HMAC 与元数据最小化、严格消息契约和受控错误。采集与 codec 共享规范化规则，消息不包含原始浏览器标识、请求对象、秘密或映射/缓存实体。
- D27：事件、发布尝试、持久化尝试与消费结果观察保持区分。VisitWriteObservations 的 COLLECTION 类别与公开 snapshot 形状保持；不增加高基数身份标签，不把本地年龄或已处理延迟当成 broker 水位，不输出敏感 payload 或驱动原文。
- D28：清理轮次与调度职责继续分离。按上海窗口分批独立提交，容量、预算、失败推迟、启动/每日/积压追赶与停采继续清理保持，不将清理纳入采集启停。

### 可读性与实施顺序

- D29：显式 import、一条语句一行、统一格式与按职责排列代码；注释解释顺序、竞态和承诺。清理无用参数与纯格式变化单独审阅，不与并发状态转换混杂。
- D30：前端保持现有单页面与技术栈，仅按交互职责整理脚本和样式。永久/限时选择、校验、提交状态、结果、部分完成提示和复制交互不变，不修改前后端 URL 校验规则。
- D31：按建立基线、可读性整理、原包内生命周期分离、遗留入口收敛、核心池装配迁出、逐组搬包、HTTP/前端与文档整理、完整回归的顺序实施。每一步独立验证和记录，职责变化先于大范围目录迁移。
- D32：保持数据库表结构、缓存格式、消息版本、HTTP 路径/响应/错误码、配置键、设施命名和容量语义。同步架构、运行、维护和测试导航，沿用现有领域词汇与 ADR；按依赖逆序回退，不进行整个工作树的破坏性恢复。

## Testing Decisions

用户于 2026-10-03 明确确认：以现有 HTTP 行为和真实 Spring 启动/关闭作为主要验收入口，辅以现有缓存、发号、持久化和消息接缝做故障注入，保持现有业务契约。

- T01：好测试断言调用者可观察的行为、承诺和资源隔离，不断言私有字段、锁数量、精确内部调用顺序或新类数量。结构检查另核对目标归属、依赖方向与可见性，不能用它代替运行验收。
- T02：优先最高现有 seam：HTTP 请求验证创建、跳转、启禁用、鉴权、采集与统计表示；真实 Spring context 验证 ready/close 与资源所有权。参考 ShortLinkApiTest、InternalManagementApiTest、VisitMqShutdownTest 和 AsyncVisitStartupRecoveryTest。
- T03：核心行为覆盖固定编码向量、边界长度、独立发号与提交、主键冲突重试、部分完成及协调恢复。沿用 PermutedShortCodeEncoderTest、ShortLinkUseCasesTest 和 ShortLinkStateServiceTest，既有 Clock、发号与缓存 seam 继续可替换。
- T04：缓存通过现有用例和真实 Redis/MySQL 验证三种拒绝结果、过期优先、条件回填、版本隔离、迟到结果、并发共享、超时与任务失败清理。沿用 RedisRedirectCacheTest、RedirectLoadCoalescingTest 和 RedisRedirectIntegrationTest；需要证明查询减少时观察实际 SQL/受控读取，不仅比较响应。
- T05：管理保护搬迁后验证未配置关闭、缺失/错误/重复令牌，以及拒绝先于参数和请求体解析；GET、HEAD 与状态修改都不能绕过。沿用 InternalManagementConfigurationTest、InternalManagementDisabledApiTest 和管理 HTTP 测试。
- T06：逐请求采集验证缓存 hit/miss 都记录独立访问事件，共享加载不合并事件，HEAD/拒绝/管理查询不记录；冻结时间、Cookie、身份隔离、元数据最小化及采集失败不改变跳转。沿用 VisitStatisticsApiTest、VisitCollectionFailureTest 和 AsyncVisitRoundtripTest。
- T07：MySQL 入口收敛后通过 VisitPersistence 验证保存、仅 eventId 重复、其他约束、执行确认丢失、确认后清理失败、繁忙和许可释放。迁移原同步 record 测试，不能用吞异常或减少断言替代；沿用 VisitConsumerIntegrationTest、VisitWriteObservationTest、VisitStatisticsApiTest 和 VisitTimeoutTest。
- T08：发布通过现有事件交接和受控 Rabbit adapter 验证容量、等待年龄、return/ACK/NACK/unknown、阻塞 sender 下的独立观察、迟到 ACK、恢复门和许可释放。保留 VisitPublisherFailureTest、VisitPublisherBrokerTest 与 VisitBacklogIntegrationTest；mock 不用于证明实际网络耗时上限。
- T09：生命周期分离新增或调整的测试必须覆盖核心 ready 后后台启动、broker 不可用仍服务、消费意图独立、关停与迟到启动/新交接竞态、重复终止不创建新 worker，以及真实 context-close 不等待卡住网络。跨生命周期测试驱动 runtime，手工装配必须注册它，不能让旧 recorder.close 暗中终止消费者。沿用 VisitMqShutdownTest、VisitCollectionLifecycleTest、VisitPausedRecoveryTest 和 AsyncVisitStartupRecoveryTest。
- T10：消费验证合法保存/重复、暂时与永久失败、有限重试、每次重试的窗口检查、超窗丢弃、未来统计日拒绝、不泄露 cause，以及真实 AUTO ACK/未 ACK 重投和 eventId 幂等。沿用 VisitConsumerTest 与 VisitConsumerIntegrationTest；可控等待仅作为内部测试 seam，保留真实设施验收。
- T11：数据库装配测试同时包含核心与统计配置，还覆盖仅核心配置存在的情况。确认核心 JdbcTemplate/事务/Mapper/发号归属、统计池懒初始化与容量/超时、统计资源耗尽不接管核心、初始化一次。参考 StatsConfigurationTest 和已有核心/统计设施验收。
- T12：查询验证范围 PV/UV、每日趋势补零与当前日语义、映射存在性、同一快照、只读隔离、繁忙/超时/错误、游标范围与跨页规则。沿用 VisitStatsQueryApiTest 和 VisitLogsApiTest，保留真实并发插入/清理的一致快照证据。
- T13：保留清理批量提交、轮次预算、容量/错误推迟、每日和积压计划、关采集继续维护与重启追赶验收。参考 VisitLogCleanupTest、VisitCleanupScheduleTest 和 VisitCleanupLifecycleTest。
- T14：安全输出与前端整理分别验证受控日志不泄露敏感信息，以及永久/限时、校验、提交恢复、结果、部分完成提示和复制反馈。日志沿用 SafeDependencyConsoleEncoderTest；前端按现有交互验证，不为排版整理新增实现镜像测试。
- T15：同包测试随 implementation 迁移，根包 HTTP/设施验收保持有意义的组织。更新 import、全限定名、构造器、注册、spy/mock 和 Bean 名；不因搬包放宽所有访问权限或弱化断言。
- T16：每步完成相关编译和定向回归，末步执行隔离环境中的完整 MySQL/Redis/RabbitMQ 验收。通过、失败、未执行与跳过分别记录。静态依赖模拟、mock 或测试数量不证明性能、消息完整性或全进程关停截止。

## Out of Scope

- 多 Maven module、微服务拆分、消息平台、前端框架或 Java/Spring/AMQP 版本升级。
- 新增领域模型副本、通用 CRUD/repository、无行为的 façade、每类一个 interface 或未来能力空包。
- outbox、可靠记账、自动同步数据库回退、统计漏记补偿、DLQ 自动回流、额外队列或跨设施原子事务。
- 数据库表/索引迁移、Redis 格式/命名空间改变、消息协议升级和 broker 拓扑/容量/TTL 调整。
- HTTP 路径、业务响应/错误码、短码编码、URL 输入范围、启禁用或缓存一致性承诺的变化。
- 近似 UV、Redis 统计投影、新汇总表、新统计缓存、吞吐优化和无证据的性能承诺。
- 新管理页面、鉴权体系、限流功能、生产故障注入或未经本规格讨论的设施变更。
