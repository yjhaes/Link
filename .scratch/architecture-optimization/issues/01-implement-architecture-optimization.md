## Acceptance criteria

- [x] 明确当前代码与测试基线，分别记录通过、失败、未执行和跳过；没有将静态检查当作设施验收。
- [x] 在职责变更前完成可审阅的可读性整理，显式 import、格式、注释和无用参数清理不混入并发行为改变。
- [x] MQ 应用级 ready/close/destroy 决策由运行生命周期 module 集中；发布 recorder 不依赖 admin、listener 或消费者启停。
- [x] 核心启动不等待 broker，后台拓扑初始化和消费者启动尊重消费意图；发布恢复只影响发布连接。
- [x] 阻塞发送时独立观察有效，迟到 ACK 不覆盖终态；恢复需要 reset 完成且原发送者返回；终态与许可分别一次结算。
- [x] 关停先停止新交接并阻止迟到消费者启动，网络清理异步执行，共用有限等待预算；重复关闭不创建 worker 或重复释放资源。
- [x] 现有框架销毁 adapter 与保护保持有效，真实 Spring context-close 和消费者未 ACK 重投验收没有空跑或弱化。
- [x] MySQL 日志实现只承担 VisitPersistence，旧同步采集入口移除；保存/重复/失败、不确定与清理结果语义及容量释放完整保留。
- [x] 测试统一使用跳转 decide 后移除便利入口，创建、启禁用、拒绝结果、缓存版本、共享加载和逐请求过期行为回归通过。
- [x] 核心池装配归属清晰；统计池不接管 Mapper、发号、JdbcTemplate、事务或初始化；既有 Bean 名、配置绑定、容量和超时保持。
- [x] 全部现有生产类型具有唯一目标归属，统计按实际能力分组；消息、查询和清理没有新循环或 HTTP 实现泄漏。
- [x] 错误表示共同迁入独立 HTTP 错误 module，管理保护与根包控制器单向依赖；未配置、错误令牌、GET/HEAD 和解析前拒绝语义保持。
- [x] 保留共享事件/时间类型和已讨论的窄依赖；辅助 implementation 没有因搬包机械公开，没有新增透传 façade、通用 repository 或空包。
- [x] HTTP 逐请求采集、匿名身份、最小化元数据、消息契约、消费重试及窗口、eventId 幂等、统计快照/分页和清理追赶保持。
- [x] 观察类别、snapshot、受控日志、采集/消费开关语义与 broker policy 不变，未附带调参或改变可靠性承诺。
- [x] 同包测试随实现迁移，手工装配包含新运行生命周期，注入/spy/mock/Bean 引用完整调整；测试通过用户确认的既有行为 seam。
- [x] 前端创建、错误反馈、提交状态、部分完成提示和复制交互保持，代码分组不改变输入规则或技术栈。
- [x] 架构、运行、维护和测试文档与实际目录、依赖和资源所有权一致；遵守现有领域词汇与 ADR。
- [x] 相关编译、定向回归及隔离 MySQL/Redis/RabbitMQ 完整验收完成，无未解释跳过；未新增表结构、缓存/消息格式或 HTTP 兼容破坏。
- [x] 在任务 Answer 中记录实际变更、测试证据、限制与完成结论；仅全部验收满足后标记 resolved。

## Execution order

1. 建立基线。
2. 独立整理可读性。
3. 在原包内分离 MQ 生命周期并完成故障/关停回归。

5. 明确核心与统计池装配并验证隔离。
6. 逐组迁移统计实现及同包测试。
7. 先迁错误表示，再迁管理/统计 HTTP，整理前端与文档。
8. 完整回归、依赖/可见性核对与验收记录。

每一步保持独立可审阅和可逆。设施不可用或测试被跳过时保留明确未完成项，不降低本任务完成条件。规格发布未认领本任务，也未授权以生产故障注入完成验收。
