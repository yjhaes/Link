Status: resolved

## Problem Statement

短链接服务已经完成同步访问统计。现有实现具备统计专用连接池、写入准入、分阶段超时、失败仍正常302和事件唯一键，但获准写入的访问请求仍要在HTTP线程等待JDBC；写容量满时则直接漏记。Redis命中只减少映射读取，并不免除同步统计写入。

本阶段希望把核心跳转与非核心统计落库分开，缓冲短期访问尖峰，并形成能够解释和验证的消息发布、消费、确认与故障处理实践。当前没有生产性能证据证明必须引入MQ，不能将学习项目描述成已解决实际大规模流量瓶颈。

访问统计用于流量观察，继续接受故障漏记；它不是可靠计费账本。引入消息队列不能让正常跳转新增MQ网络等待、统计数据库等待或启动硬依赖，也不能引入无界缓冲、无限重投和复杂补偿基础设施。

## Solution

每个符合统计口径的GET在通过最终逐请求校验、作出正常跳转决定后，同步识别匿名访客、构建Cookie、最小化元数据并冻结访问事件。请求仅尝试立即交接到有界本地缓冲，随后返回原302；后台Producer发布RabbitMQ消息，同应用内的独立统计Consumer同步写入MySQL访问日志。

使用一个RabbitMQ节点、一个持久化direct业务Exchange及classic业务Queue，发布与消费分离连接。增加单一DLX/DLQ用于失败排查，不自动回流。Consumer使用Spring AUTO确认、已有eventId唯一键和每轮有限分类重试，明确区分已保存、合法重复、过期丢弃、失败及提交不确定。

保持跳转优先及best-effort契约：采集失败、缓冲满、发布失败/不确定、进程退出和队列容量/TTL淘汰允许漏记，不同步回退MySQL、不自动重投失败发布事件。MQ不可用时核心仍能启动和跳转；积压与依赖故障通过有界资源、受控观测和人工暂停处理。

MySQL访问日志继续作为PV/UV查询依据，保留匿名Cookie身份、上海统计日、最近30个统计日、内部管理令牌、范围UV去重、查询一致快照、明细分页和日志清理规则。查询改为异步可见，正常以数秒可见为起始目标，故障和积压不提供固定延迟保证。

### 口径、权威数据和替代范围

- 延续既有领域术语和已接受的同步统计业务规则，以异步采集边界替代请求内同步持久化。MySQL访问日志仍是唯一统计权威；不新增计数表、日汇总表、Redis统计Counter/HLL或统计双写。
- 访问事件仅由采集开启后的正常GET跳转决定产生；HEAD、拒绝结果、创建、状态维护及查询不产生事件。缓存hit/miss及共享加载等待者逐请求统计，符合口径的机器人GET继续计入。
- 服务端跳转决定不证明响应发送成功或原始URL已打开。客户端重新GET为新事件，内部重试/重投/重放沿用原事件；跳转优先、故障允许漏记，不承诺可靠入账。
- 保留匿名Cookie、按短码隔离HMAC、密钥版本、上海统计日、单短码大小写敏感维度、30日查询窗口和已有清理规则。范围UV对整个查询范围去重，不能相加每日UV。

### 模块和接缝

- 保持RedirectService的逐请求决定边界及原Redis协议；不将MQ调用、统计失败、ACK或重试引入核心映射加载、缓存回填及状态事务。
- 沿用VisitCollection在Web入口提取数据，以及VisitRecorder这一现有统计提交接缝；在统计功能中提供有界提交、后台发布、消息转换、消费持久化及生命周期职责。HTTP仅交接事件，不创建通用消息平台或大量透传接口。
- 同步完成方法/开关判断、Cookie、HMAC、元数据最小化、eventId及决定时刻冻结。后台只接收独立数据，不保留Servlet请求/响应或原始浏览器标识；实际发布可以发生在响应返回前或后，不依赖响应完成回调。
- 请求不等待可用缓冲、MQ建连/channel/发送/确认或统计SQL，不使用CallerRuns策略；核心映射查询仍按原实现运行，不宣称整个HTTP没有网络访问或严格墙钟上限。
- 已合法构建的新Cookie可以在交接或发布失败时随302返回，保持既有属性及生命周期。采集关闭不产生新事件或Cookie，不使用共享默认身份兜底。
- 消费持久化需要明确的成功或失败反馈。现有MySqlVisitRecorder吞异常并返回void，不能直接作为消费成功证明；改造其持久化边界为明确已保存/合法事件重复或传播失败，HTTP提交适配器继续处理尽力降级。尽量复用单条插入和现有池/准入，不为测试扩散仓储接口。

### 消息协议

- 消息体上限16KiB；仅包含下表字段，可空元数据缺失为null。Producer最小化、Consumer校验schema/格式/必填/长度/摘要及日期一致性，仅解析预期事件类型。

| 字段 | 契约 |
| --- | --- |
| schemaVersion | 必填整数，第一版1 |
| eventId | 必填UUID文本；同事件内部处理保持不变 |
| shortCode | 必填，既有4～8位字母数字规则、大小写敏感 |
| occurredAt | 必填ISO-8601 UTC毫秒时刻，从最终逐请求决定冻结 |
| statDate | 必填YYYY-MM-DD，等于发生时间的Asia/Shanghai日期 |
| visitorHash | 必填规范Base64，解码32字节，按短码隔离的HMAC摘要 |
| visitorKeyVersion | 必填整数1～65535，与schemaVersion不同 |
| peerIpNetwork | 可空，最多49字符，沿用IPv4 /24和IPv6 /48最小化 |
| userAgent | 可空，清理控制字符，最多512个Unicode字符 |
| refererHost | 可空，规范化合法host，最多253字符 |

- 不传原始URL、Cookie、完整IP/Referer、整组请求头、令牌/密钥/连接秘密、请求响应、映射实体、缓存状态/版本、自增日志ID或预计算PV/UV。消息体最小化不表示这些访问数据不需要保护。

- 单节点RabbitMQ，同一Spring Boot应用中的独立统计listener；不拆统计微服务。发布与消费使用分离连接，消费继续使用统计专用池，核心数据源/MyBatis/事务与初始化归属保持不变。
- 不增加数据库表、迁移或永久去重记录；继续使用现有日志eventId唯一键、自增排序ID及查询/清理索引。当前只插日志；其他约束或SQL错误不当作事件重复。
- Exchange/Queue明确durable，Queue为classic、非独占、非自动删除；业务消息持久化。单节点及classic不构成高可用保证，同进程和MySQL仍共享资源。

| 角色 | 名称/绑定 |
| --- | --- |
| direct业务Exchange | shortlink.visit.x |
| 业务Queue | shortlink.visit.stats.q |
| 精确业务routing key | visit.occurred.v1 |
| direct DLX | shortlink.visit.dlx |
| DLQ | shortlink.visit.stats.dlq |
| 精确死信routing key | visit.failed.v1 |

- 只绑定一个业务统计队列；业务队列DLX和死信key指向单DLQ，DLQ无回流DLX或自动消费者。direct key是精确匹配，不使用topic通配。
- 可变化的TTL、容量及DLX优先以受控policy管理，固定类型通过声明明确。队列属性冲突不能靠不同参数重声明更新，不自动删除积压；声明错误进入统计降级并提示维护修复。

### 发布、确认及恢复

- 启用correlated publisher confirms及mandatory/returns，区分本地交接、发送尝试、broker确认/路由和数据库保存。正常发送返回不等于broker接受，confirm ACK也不等于Consumer成功；出现return后不能因随后ACK记为路由成功。
- 发送异常、return、nack和确认未知受控观测；不能仅凭异常断言未执行。确认观察超时记结果不确定，不自动重投失败事件，不同步回退MySQL；连接恢复仅处理后续仍符合待发预算的事件，不构成历史补采。
- 缓冲、未确认及活跃channel有限。关联状态按发布尝试只终结一次，超时/return/关闭生成的framework nack/迟到回调不得重复计数或释放许可；回调不阻塞业务且不向HTTP传播异常。
- 独立于sender的观察任务回收框架关联及故障发布资源，只重建publisher子连接，不reset主消费连接。最多一个恢复动作；关闭未完成时不无限创建替代worker、线程或连接，暂停发送并继续有界降级。
- 建连、握手、channel获取、心跳及confirm观察分别约束，核验实际效果；5秒确认观察不取消已执行或阻塞的发送，不虚构总publishTimeout或端到端发送截止。

### 消费结果、ACK及重试

- 使用同步listener、Spring AUTO及batchSize=1；数据库处理完成后才正常返回，不在listener中提交另一个异步任务就返回。不使用NONE，当前不要求手写MANUAL ACK。
- 已确认保存、仅事件唯一键重复、合法超窗事件有明确终局；繁忙/失败/未知提交必须传播消费错误，不能使用吞异常的正常返回误ACK。确认保存后的资源关闭错误保留SAVED。
- 复用现有唯一键处理数据库提交与ACK间隙的重投。消息可能多次处理，业务查询仍按日志行计PV；发布/保存确认指标不能代替PV。
- 暂时性连接/获取超时、断连、锁等待、死锁、繁忙或提交不确定，每轮最多3次（含首次）；两次重试前分别等待200ms/500ms，同一ID和冻结数据，仅占消费线程。间隔不等于整个消费耗时上限。
- 格式、转换、未知schema、字段校验和永久约束/SQL错误直接拒绝。按cause分类，不照搬全异常重试；耗尽必须拒绝且不requeue，不允许recoverer吞失败后AUTO误确认。
- 本轮stateless重试不限制跨重启累计处理次数；未ACK断连可重投开始新一轮，x-death只记录死信，不能用作普通requeue计数。无多级延迟队列或自动无限重试。

### 死信、窗口和持续故障

- 最终拒绝及业务TTL到期通过DLX进入单DLQ，供受限排查；classic死信转移、TTL及容量均可能丢失，不作可靠补偿存储承诺。
- 人工重放前先修复故障，限定选取范围，保持原ID和冻结数据并检查窗口；不为重新入账改时间。读取后重新发布时，确认新路由已接受再移除原死信，未知确认不能宣称完成。当前不编写自动重放工具。
- 合法迟到/乱序按原发生时间记录，不重新判断映射当前禁用/过期状态。每次实际持久化尝试前检查当前上海日及其前29日，重试跨午夜重新检查。
- 早于窗口的合法事件记expired并成功返回ACK丢弃；未来统计日及日期不一致属不合法数据，直接拒绝。清理删除唯一记录后，旧事件也不得重新入库；不承诺无限期幂等。
- 持久化执行等待跨午夜可能留下物理超窗行，既有清理继续追赶，查询窗口仍严格。队列TTL不代替业务日期判断。
- DB持续故障时有限重试不会阻止后续事件不断死信；观察持续失败并人工暂停消费者，修复后恢复。拟提供独立消费者启用配置和修改后重启步骤，当前无现成运维命令；不新增公开管理HTTP入口或自动断路器。
- 人工暂停不同于关闭新采集；后台MQ恢复必须尊重暂停意图。停止不等于立即撤回当前或预取消息，暂停前仍可能漏记或淘汰死信样本。

### 容量、积压和生命周期

以下是可配置起点，不是压测证明的吞吐或SLA。

| 资源 | 预算 |
| --- | --- |
| 本地待发缓冲 | 256个事件，1个发布worker；满即跳过 |
| 待发年龄 | 按交接单调时间判断，超过5秒不再开始发送 |
| 未确认 | 最多32个，观察期限5秒 |
| 发布channel | 活跃最多16个，获取等待200ms；不仅设置缓存大小 |
| Consumer | 并发1、prefetch10、batchSize1 |
| 统计池 | 沿用最多4连接和写2/查询1/清理1容量 |
| 业务Queue | ready最多10000条或16MiB消息体，先到上限生效；reject-publish |
| 业务消息TTL | 该队列驻留24小时 |
| DLQ | ready最多1000条或4MiB消息体；drop-head |
| DLQ消息TTL | DLQ驻留24小时，无自动回流 |
| 单消息体 | UTF-8 JSON最多16KiB |

- 业务满队列拒收产生publisher nack，reject-publish不自动进入DLQ；不使用reject-publish-dlx。队列长度/bytes只计ready及消息体，不含unacked、headers或全部存储开销。
- 主队列过期进入DLQ后再计DLQ驻留TTL，两个24小时可合计接近48小时；TTL不承诺到时立即物理删除，也不替代unacked和业务窗口处理。
- 积压先核验listener运行、DB耗时/错误、broker资源告警和消费速率；提高并发前核验全实例数据库容量，不无限增加缓冲或prefetch，必要时暂停消费或停止新采集，核心继续跳转。
- MQ声明和listener启动在核心启动后后台执行，不让MQ网络失败取消或阻塞核心启动；默认auto-start或仅调整missingQueuesFatal不足以证明这一点。静态非法配置仍按配置错误处理；认证及声明冲突观测并维护修复。
- 新采集开关保持原义，关闭不影响已入MQ消息消费、历史查询和清理；不自动切回同步统计、不补采停采期间访问。
- 停机停止新交接，终止恢复任务并有界释放资源，不无限drain；未发送进程内事件允许丢失，未确认不能声称未送达，未ACK重投由唯一键处理。生命周期阶段等待不等于整个进程或所有销毁方法的硬截止。

### 查询、观测和实施分级

- 不新增或改变统计HTTP接口、鉴权、默认日期/页大小、错误码、范围UV、同快照汇总/趋势、明细游标或缓存控制；已有过期/禁用映射的历史查询规则保持。
- collectionPolicy仍best-effort，collectionEnabled只代表采集配置，generatedAt只是响应生成时间；query快照不代表此前消息已全部处理。
- 分层观察本地接受/满/过期、队列及未确认数、confirm/return/nack/unknown、保存/重复/expired/失败/重试耗尽、消费速率及处理延迟。区分事件和尝试；已处理事件延迟及本地最老年龄不冒充broker精确最旧事件年龄或消费水位。
- 指标使用固定类别，不以短码/IP/访客作无限标签；受控日志可关联事件ID，不输出消息体、摘要、原始请求、密钥令牌、连接秘密及驱动原文/堆栈。包括框架ErrorHandler、recoverer及转换错误在内都要核验，不照搬默认敏感日志。
- 已确定的最小拓扑、事件最小化、资源/生命周期隔离、confirm/returns、持久化反馈/AUTO、唯一键、有限重试/DLQ、窗口/容量/TTL、基础观测及人工暂停为必须实现。
- 批量落库、测量后的有限并发优化、受控重放工具、自动暂停/探测恢复及更完整指标接入为可以实现的后续项，不纳入当前验收。
- outbox/本地消息表、MQ/分布式事务、quorum集群、多级延迟重试、永久去重/跨重启累计投递上限、MANUAL ACK及端到端恰好一次边界只需要理解。本项目允许漏记，当前不为可靠消息产生在核心新增DB事务。
