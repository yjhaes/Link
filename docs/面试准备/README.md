## 内容分级

| 级别 | 应掌握到什么程度 | 例子 |
| --- | --- | --- |
| 必会 | 不看稿能解释问题、项目做法和一条限制 | 创建/跳转流程、缓存三类问题、MQ 幂等、令牌桶 |
| 进阶 | 能指出源码入口，用具体先后顺序解释竞态 | 迟到旧回填、等待超时、DB 保存后 ACK 丢失、状态行锁 |
| 扩展 | 知道什么时候需要及其新增成本；不说成已实现 | Bloom Filter、跨实例回源锁、outbox、Redis 高可用、分库分表 |

框架原理参考官方文档，项目事实以当前代码和实际验收为准。历史测试数量和观察结果需附对应版本，不当作当前工作树重跑证明。

## 回答组织方式

先说业务问题，再说项目选择，最后补证据和限制。以击穿为例：

> 热门短码缓存过期时，交叠请求会重复查数据库。我在单实例内按短码和缓存版本共享一次正在执行的加载，用查询计数和受控并发测试验证。它不跨实例合并，等待超时也允许额外回源。

避免只列“用了 Redis、RabbitMQ、Lua”，也避免没被追问就展开所有线程、超时和关闭细节。

## 面试前必会清单

- 能分别画出创建与跳转链路，说明 MySQL、Redis、RabbitMQ 各负责什么。
- 能解释 Base62 为什么不自动保证唯一，以及项目的三层唯一性来源。
- 能区分穿透、击穿和雪崩，并说出对应措施的限制。
- 能用 A/B 请求先后顺序说明旧回填问题和版本协议。
- 能区分本地交接、broker 确认和数据库保存。
- 能说明同一事件重投与浏览器刷新为什么不同。
- 能解释 PV、UV、HEAD 和跨日范围去重。
- 能解释令牌桶允许突发，限流额度和并发准入不是同一件事。
- 能解释数据库已提交后发生 Redis 故障，为什么不能当作回滚或盲重试 POST。
- 能举出一个真实测试入口，并说明它证明和没有证明的内容。
- 能回答“项目里最难的问题”“还有哪些不足”“下一步怎么改”。

准备材料时从 [最短演示](../../README.md#最短演示)开始，源码职责见 [当前架构](../架构与原理/architecture.md)。故障操作仍放在 [故障排查](../README.md#故障排查按需阅读)，面试时先解释原理，再决定是否展示。
