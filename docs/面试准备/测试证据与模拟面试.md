# 测试证据与模拟面试

返回 [面试导航](README.md)。本篇用于把“我实现了”转换成“我知道怎样证明”，并检查自己能否承接追问。

## 1. 如何回答“你怎么测试的”

> 我把验证分成纯用例、Spring/HTTP 装配和真实设施三层。用例测试控制时钟、随机值、查询次数及请求先后顺序；HTTP 测试看状态、响应头和拒绝请求是否产生副作用；真实 MySQL、Redis、RabbitMQ 验证提交、TTL、Lua、路由、重投和唯一键。性能观察与正确性分开，附环境、版本和限制。

| 层次 | 可以证明 | 不能独自证明 |
| --- | --- | --- |
| 编码/用例测试 | 规则、边界、受控竞态、调用次数、异常分支 | 真实 SQL、网络和设施配置有效 |
| Spring/MVC/真实 HTTP | Bean 装配、拦截器顺序、参数解析、状态和响应头 | 每个真实 broker/数据库故障行为 |
| 真实设施集成 | 序列化、TTL、事务、唯一键、路由/ACK/重投 | 生产容量、高可用或任意故障不丢消息 |
| 有限性能观察 | 在注明条件下的响应分布、成功/拒绝比例与资源数据 | 无条件性能提升、最大 QPS、生产 SLA |

仓库 [历史验收](../测试与验证/verification.md)记录特定源码版本的 317 项 Java 测试。可以说明曾有分层验收，不能把这个数字说成本轮刚跑的结果，也不能只用数量证明质量。

## 2. 四个值得展示的验证场景

### 场景 A：同码击穿是否真的减少查询？

1. 让首个请求进入数据库查询后暂停，确保缓存仍未有业务结果。
2. 启动第二个同码同版本请求，确认它正在等待共享加载。
3. 在释放首个查询前断言 SQL 计数为 1，释放后检查结果一致。
4. 另外验证不同短码能同时查询、超时允许独立回源、失败后任务被清理。

仅看两个响应都是 302 不足以证明只查了一次；只加 sleep 也不能确定请求确实交叠。入口：[RedirectLoadCoalescingTest](../../src/test/java/com/example/shortlink/service/RedirectLoadCoalescingTest.java)。

### 场景 B：旧结果为何不能覆盖新状态？

控制 A 读到旧状态后暂停，B 更新数据库并完成版本协调，再恢复 A。需要同时检查旧版本回填被拒绝、变更后新请求不加入旧任务，以及共享结果使用时到期仍被拒绝。

只验证 Redis 中没有旧值还不够：新请求可能已经从旧 Future 得到旧 404/403。入口：[真实 Redis/数据库测试](../../src/test/java/com/example/shortlink/RedisRedirectIntegrationTest.java)及上述加载合并测试。

### 场景 C：重投是否只记录一次？

把同一个 eventId 的消息交给消费者多次，检查最终只有一条事件日志；再用不同 eventId、同一访客的两个事件，检查 PV 增加而 UV 仍按范围去重。其他唯一约束错误不得误当作重复成功。

ACK 丢失或保存结果不确定要用真实设施/驱动边界补充验证，不能仅 mock 一次正常保存就宣称重投安全。入口：[消费者用例](../../src/test/java/com/example/shortlink/stats/messaging/VisitConsumerTest.java)、[统计写入观察测试](../../src/test/java/com/example/shortlink/stats/persistence/VisitWriteObservationTest.java)。

### 场景 D：回源上限是否限制真实查询？

阻塞已进入的实际查询，再发起不同短码的 miss，验证准入不足立即拒绝；查询异常后许可仍可释放。缓存命中与共享等待者不额外占许可，缓存回填慢也不继续持有已完成 SQL 的许可。

入口：[RedirectLoadProtectionTest](../../src/test/java/com/example/shortlink/service/RedirectLoadProtectionTest.java)。这里证明的是实际查询并发与许可释放，不是所有 HTTP 线程数量或每秒请求数。

## 3. 故障场景怎么回答

先说具体操作与阶段，再说明已确认的结果。不要只看到一个 503 就判定一切回滚。

| 面试场景 | 当前行为与回答重点 |
| --- | --- |
| Redis 不可用时创建 | 限流失败在业务前拒绝，不发号写库；与已提交后的协调失败区分 |
| Redis 不可用时跳转 | 限流阶段放行；缓存无法确认则查 MySQL，仍受每实例 SQL 并发准入保护 |
| MySQL 创建已提交，Redis 协调失败 | 带短码的部分完成 503，仅恢复协调，不重复 POST |
| 热门短码加载者慢 | 等待者有共享等待预算，超时重读缓存或独立回源，不取消其他请求的加载 |
| MQ 不可用 | 核心跳转可继续，统计允许漏记；重连不证明丢失的本地事件被补齐 |
| 消费后保存成功，ACK 丢失 | 可能重投，eventId 唯一键防重复入账 |
| 数据库查询异常 | 不能缓存成 404，也不能把统计读取失败表示成零访问 |
| MySQL 故障但有跳转缓存 | 核心就绪检查可能失败，部分有效缓存命中仍可能直接跳转；不能据探针断言所有接口行为 |
| 恢复了旧 Redis 快照 | 值与版本可能一起回滚，按受控恢复处理，不宣称版本机制自动解决 |

这里只讨论行为。故障注入和清理步骤需要隔离环境，具体操作留在 [故障排查导航](../README.md#故障排查按需阅读)。

## 4. 被问“系统变慢怎么排查”

可以按这个顺序组织回答，不必先启动完整监控平台：

1. 确认慢的是创建、跳转、统计查询还是统计可见性；区分 200/302 与 429/503 的数量和耗时。
2. 跳转检查缓存命中/回源、Redis 错误、实际 SQL 并发及拒绝，不把快速失败当快速成功。
3. 数据库检查连接池等待、SQL 时间、锁等待和扫描情况；增加池容量前确认数据库是否能承受。
4. 统计检查本地交接、未确认发布、broker 积压、消费结果与落库；confirm 成功不能替代 PV 验证。
5. 核对最近改动、配置和访问分布；在隔离环境重现，比较相同条件下的成功比例和耗时分布。

现有观察入口见 [健康](../故障排查/health.md)、[日志与指标](../故障排查/observability.md)。不要在排查例子中把 URL、令牌、Cookie 或 MQ payload 打进普通日志。

## 5. 没有生产压测，如何描述优化结果？

可以描述可直接核对的结果：同码交叠 miss 共享一次实际查询；TTL 在配置边界内；旧版本回填被拒绝；统计 JDBC 不在 HTTP 线程执行；并发准入不足立即拒绝。

性能百分比则需要可比较的基线、环境、数据量、命中率、并发、持续时间和成功/拒绝比例。历史观察附件不完整时，不把摘要当作当前可复现容量证明。测试通过和代码结构都不能推出“提升 55%”或“万级 QPS”。

## 6. 一轮模拟面试

先不看答案逐题说，再回到专题核对。表中是回答应覆盖的内容，不是唯一话术。

| 顺序 | 面试官问题 | 合格回答应包含 |
| --- | --- | --- |
| 1 | 两分钟介绍这个项目 | 功能、三项基础设施、主链路、两三个重点、项目定位 |
| 2 | 创建短链接如何保证唯一？ | 发号、双射前提、数据库约束；Base62 只是编码 |
| 3 | 请求超时后客户端直接重试创建，行吗？ | 不确定提交状态、重复映射、没有幂等键、协调未确认的短码 |
| 4 | 缓存穿透、击穿、雪崩分别如何应对？ | 场景、负缓存、加载合并、抖动与回源限制的不同职责 |
| 5 | 两个应用实例访问同一码，会只查一次吗？ | 不跨实例合并；已确认版本、正常交叠和超时前提 |
| 6 | 仅修改后删缓存为何不够？ | 旧查询暂停/迟到回填；Lua 版本校验与任务版本隔离 |
| 7 | MQ confirm 成功，就说明统计成功吗？ | 本地、broker、DB 三个结果；consumer ACK 另一个方向 |
| 8 | 为什么数据库唯一键能处理重投？ | 同 eventId、并发插入约束、ACK 丢失；不是端到端恰好一次 |
| 9 | 两天每天 UV=1，两天 UV 一定为 2 吗？ | 范围去重、同匿名身份可为 1、密钥版本变化限制 |
| 10 | 为什么 Redis 限流失败有时放行、有时拒绝？ | 跳转优先、创建/管理保守；放行仍有回源准入 |
| 11 | 用 Future 就不会阻塞 HTTP 线程吗？ | 当前等待者 get 会等待；后台统计与加载合并分开 |
| 12 | 你最难的问题和下一步改善是什么？ | 本人参与范围、具体竞态、验证证据；先需求/测量后选变化 |

## 7. 如何给自己打分

每个必会问题按下面三个条件自查：

- 能说清业务场景和项目当前做法，避免堆术语。
- 能指出一个源码/测试入口，或用明确先后顺序举例。
- 能说清一条限制，不把扩展设计冒充已实现能力。

三条都能做到，再继续准备进阶追问。只会背一个概念名，就回到对应专题看实际代码；没有本人经历的故障案例，可以说“测试里覆盖了”，不要包装成生产事故。
