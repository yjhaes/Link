## 第一轮已确认：口径与优先级

- Q1：每个通过短码和有效性校验、进入正常 302 跳转路径的 GET 请求计一次 PV。刷新和客户端重试分别计数；404/403/410/500、HEAD、创建及统计查询请求不计。第一版不识别机器人，符合口径的爬虫与预览器 GET 也计数。
- 采集边界是服务端通过最终逐请求校验并作出正常跳转决定，不能证明目标网站已被打开，也不能把客户端断连或响应发送失败描述为目标网站成功访问。统计等待期间的处理按已确认 Q13 执行。
- Q2：采用随机匿名访客 Cookie，UV 按匿名访客标识去重，不使用 IP 或 IP＋User-Agent 作为 UV 身份。指标不代表真实人数；Cookie 缺失、被拒绝及生命周期按已确认 Q5 执行。
- Q3：第一版按单条短链接映射提供按日 PV/UV 趋势和指定日期范围汇总，日界线固定为 Asia/Shanghai。两个短码指向同一原始 URL 仍分别统计。范围 UV 对整个范围去重，不能将每日 UV 相加；暂不提供全站、按目标 URL、小时或地域统计。
- Q4：跳转优先；统计失败、超时或提交结果不确定时仍继续正常 302，允许故障期间漏记。统计用于流量观察，不承诺每次访问都可靠入账；统计操作使用有界超时，不在跳转请求内反复重试，并记录失败指标。
- 失败隔离必须考虑同步等待和资源竞争，仅捕获异常不能保证跳转延迟和可用性；具体预算见同步资源约定，已确认的单一日志存储方案不引入 MySQL/Redis 统计双写。

## 当前代码的约束

- 现有跳转入口在 `ShortLinkController`，调用 `RedirectService.findOriginalUrl` 后生成 `302`、`Location` 和 `Cache-Control: no-store`。
- `RedirectService` 按“短码＋缓存版本”合并实例内的数据库加载，每个请求使用结果时独立复查业务过期边界。
- 访问统计必须逐 HTTP 请求发生，不能放入共享数据库加载或缓存回填，否则会漏记缓存命中的访问并少算并发访问。
- 跳转缓存继续遵守 ADR-0003/0004；统计存储的可靠性和恢复规则需要独立讨论，不能直接套用可丢弃的跳转缓存规则。
- 现有架构文档建议将统计职责放在未来的 `stats` 功能中，并在 Web 入口提取 HTTP 元数据。统计不能复用缓存对象、HTTP 请求 DTO 或短链接映射实体作为访问事件。
- 当前没有用户、登录鉴权或映射所有者字段；现有启用/禁用接口定位为受信任内部管理，尚未实施令牌鉴权，不能假设统计查询和明细访问已经具备权限隔离。
- 现有 MySQL 时间字段使用 `DATETIME(3)`，应用按 UTC 读写，注入的时钟为 `Clock.systemUTC()`；当前代码尚未实现统计日分桶，已确认设计按 Asia/Shanghai 划分。
- Redis 连接和命令超时默认均为 200ms；当前配置未显式约束 MySQL 连接、查询、socket 和连接池等待时间。同步统计的超时与资源预算不能直接视为已经具备。

以上是已读取代码和文档的事实，不是本阶段已经实现统计的声明。Spring MVC 对 GET 的隐式 HEAD 支持尚未在当前项目实际验证，验收设计应明确覆盖。

现有测试提供可控时钟、mapper/cache 替身、闩锁控制的请求合并验证、真实 MySQL 8.4 与 Redis 7.2 集成测试，以及两个独立应用实例的验证基础。真实 Redis 超时测试已承认命令可能超时后才执行，因此不能因超时就假设统计操作没有生效。统计具体验收计划见下文，不在本轮修改测试代码。

## 第二轮已确认：匿名访客 Cookie、存储与访问控制

- Q5：请求没有 Cookie 或标识格式非法时，生成新的随机匿名访客标识，本次访问立即参与 UV，并通过本次正常跳转响应设置 Cookie；不回退到 IP 或 IP＋User-Agent 指纹。
- Cookie 固定保留 30 天，命中不续期；仅限当前主机（不设置 Domain）、Path=/s、HttpOnly、SameSite=Lax，HTTPS 部署开启 Secure。过期后重新生成的标识是新的匿名访客。
- 第一版接受拒绝 Cookie、清除 Cookie、Cookie 提前丢失以及首次并发访问造成的 UV 偏高。服务端首次收到无 Cookie 请求时无法判断客户端是否会保存响应 Cookie，不声称已经识别出浏览器拒绝 Cookie。
- Cookie 标识格式和随机性按 Q15 及采集流程执行；原始 Cookie 不落库，日志使用按短码隔离的 HMAC 访客摘要。该标识不承担认证或授权职责。
- 每次符合 PV 口径的访问同步插入一条 MySQL 访问日志；PV 从日志条数取得，UV 对同一查询范围内的匿名访客标识去重。统计失败时按 Q4 尽力继续跳转，因此日志中的准确计数不等于访问无遗漏或真实人数。
- 第一版不维护 Redis 统计 Counter/HLL，也不做 MySQL/Redis 统计双写；Redis 保持现有跳转缓存职责。Counter/HLL 的适用条件和限制仍在本文中讨论，作为后续优化知识，不因此增加实现。
- 统计查询、启用及禁用接口均属于受保护的内部管理接口；通过请求头传递独立访问令牌，未配置时关闭，不依赖公开短码作为权限凭证。本阶段不增加用户、登录及链接所有者体系。
- 当前已经有 `PUT /api/links/{code}/enabled`；本阶段补充该现有接口与统计查询使用相同令牌保护，不新增第二个启用/禁用路径。
- 启用/禁用行为继承 ADR-0004/0005：数据库状态提交后受控轮换 Redis 版本并清除结果，最多尝试三次、重试前分别等待 50ms 和 100ms，确认协调后才返回 200；已提交但协调未确认返回带短码的专门 503，不能声称回滚。重复启用/禁用返回 409，已过期映射的所有新状态操作返回 410。状态判断与更新使用 MySQL 行锁事务；本轮不改变这些已接受语义。
- 现有协调恢复方法只轮换缓存版本，不重写 enabled；本轮不会因为 Q7 的访问控制要求自动新增恢复 HTTP 接口。若后续确有需要，另行设计；现有方法只能由受信任内部维护调用。

## 第三轮已确认：字段最小化与保留窗口

- Q8：保留事件 ID、短码、UTC 毫秒访问时间、按短码隔离的 HMAC 访客摘要、IPv4 /24 或 IPv6 /48 脱敏网段、清理控制字符且最多 512 字符的 User-Agent、规范化 Referer host。原始 Cookie、完整 IP、完整 Referer 的路径和参数、整组请求头及令牌不落库。不保存原始 URL 副本、地理位置、UA 解析结果。
- 访客摘要由独立密钥对短码和 Cookie 随机标识计算 HMAC；不同短码使用不同摘要，不能直接据此关联跨短码访客。它与脱敏 IP 仍是需要保护的访问数据，不能宣称完全匿名。
- Referer 只保留合法规范化 host，缺失或非法允许为空，不解释为一定是直接访问；User-Agent 清理控制字符后限长，缺失允许为空。不得把请求头直接写进错误日志或将其视为可信身份。
- Q9：统计查询严格只覆盖最近 30 个上海自然日（含今天），在线日志按这个窗口每日批量清理；清理延迟时也不向查询者返回已过期数据。30 日是严格的查询窗口及清理目标，不是数据库故障或积压时的物理删除硬截止时间，具体维护预算已随 Q17 确认。不提供终身累计，删除明细后不能再据此恢复旧 PV/UV，也不能通过每日 UV 数字相加恢复任意范围 UV。
- 数据库访问时间仍按 UTC 保存，按上海日界线分桶。字段类型、索引、批量清理方式及权限细节见下文的具体约定。

## 数据模型的具体约定

`short_link_visit_log` 只追加访问记录，保留窗口外可以批量删除；不修改某个访客的历史日志来增加计数。事件 ID 在进入存储之前生成，数据库行 ID 仅服务于存储与分页，二者承担不同职责。

| 字段 | 类型与空值 | 含义 |
| --- | --- | --- |
| id | BIGINT，自增主键，非空 | 数据库行标识，作为同时间明细的分页排序依据 |
| event_id | BINARY(16)，非空，独立唯一约束 | 应用生成的 UUID 访问事件标识；固定 16 字节格式 |
| short_code | VARCHAR(8)，utf8mb4_bin，非空 | 与映射表采用相同的大小写敏感规则；逻辑引用 |
| occurred_at | DATETIME(3)，非空，UTC | 最终逐请求检查通过、作出跳转决定的时刻 |
| stat_date | DATE，非空 | 由 occurred_at 按 Asia/Shanghai 计算，不能来自插入完成时间 |
| visitor_hash | BINARY(32)，非空 | 按短码隔离的 HMAC-SHA-256 访客摘要 |
| visitor_key_version | SMALLINT UNSIGNED，非空 | 明确摘要密钥版本；同一版本对应固定密钥 |
| peer_ip_network | VARCHAR(49)，可空 | 观察到的对端 IP 脱敏网段，包含 /24 或 /48 |
| user_agent | VARCHAR(512)，可空，utf8mb4 | 清理控制字符、按完整 Unicode 字符限长的 UA |
| referer_host | VARCHAR(253)，可空 | 合法、规范化的来源 host；没有路径、参数、用户信息或端口 |

不增加 recorded_at、原始 Cookie、完整 IP、目标 URL 副本、整组请求头、状态快照或地理位置。当前只记录作出正常跳转决定的事件，日志表不承担拒绝请求审计。

建议索引为事件 ID 唯一索引、`(short_code, stat_date, visitor_key_version, visitor_hash)` 聚合索引、`(short_code, occurred_at, id)` 明细索引和 `(stat_date, id)` 清理索引。按实际查询用 EXPLAIN 验证，不宣称加索引后任意范围去重均是常数时间。每个二级索引增加写入和存储成本；自增主键避免将随机事件 ID 用作聚簇排序依据。

不加外键是主动取舍：逐次跳转已判定映射可用，日志写入不再重新校验或对映射加锁。应用负责只从合法访问事件写入短码；不存在短码不会进入正常记录链路。当前没有删除映射 API；将来删除映射时须重新明确日志保留、查询和删除职责，不能假设数据库会自动级联清理。

事件唯一约束用于同一事件重放的去重，不对同一 Cookie 的多次访问去重。第一版不重试写入，因此它是低成本的持久化保护及后续处理边界，不代表已经可靠投递或实现消息消费。不能把任意唯一约束错误或其他数据库异常都吞成“重复事件”。

## 采集边界与同步流程

1. 短码校验、缓存/数据库解析与业务有效性判断继续由跳转用例完成。共享加载只共享映射结果；每个请求仍在使用结果时复查过期边界。
2. 通过最终逐请求检查时，给本次决定确定 UTC 毫秒发生时间。跳转用例需要从当前只返回 URL 的结果调整为携带原始 URL 与已冻结决定时刻的用例结果；同一个时刻用于最终过期检查和事件分桶。这个时刻在每个请求使用共享结果时各自形成，不能放进共享加载结果，也不能由控制器事后再次读取 Clock 推测。HTTP 入口识别方法，仅 GET 产生事件；HEAD 保留跳转响应行为，但不生成事件或访客 Cookie。
3. Web 采集边界读取 Cookie、连接对端地址、UA 和 Referer，并在生成事件之前完成访客摘要与脱敏。可以调用不依赖 Servlet 的规范化函数；传入记录器的事件只有已确认字段，不含 HttpServletRequest、原始 Cookie、原始 IP、完整 Referer 或令牌。
4. 对合法 Cookie 沿用标识，不续期；缺失、非法或同名多值无法明确时生成新随机值。Cookie 建议名为 `sl_visitor`，规范的无填充 Base64URL 为 22 字符，并验证解码为 16 字节且重新编码一致。通过正常 302 响应设置已确认的 30 天属性。
5. 写入准入失败立即跳过日志并记录 dropped，Cookie 仍可正常设置；有容量则在统计专用连接上同步提交单条访问日志，不更新映射、不调用 Redis 统计命令、不加入创建或状态变更事务。
6. 写入失败或提交结果不确定时记录受控失败指标，不重试、不取消已经确定的跳转；合法 GET 继续生成 302、Location 和 no-store。不能因超时就断言日志必定未保存，也不能以记录失败改写成业务拒绝。

身份摘要输入采用有版本和无歧义边界的编码，包括用途标识、密钥版本、大小写敏感短码和 Cookie 的随机字节。独立 HMAC 密钥至少 32 个随机字节，无默认共享秘密；所有实例配置一致。Cookie 本身是统计身份，不承担认证；固定格式校验不等于防机器人或不可伪造。

第一版 IP 来源严格为连接对端，明确停用对外部 Forwarded/X-Forwarded-For 的自动信任。IPv4 保留前 24 位，IPv6 保留前 48 位，其余位清零；IPv4-mapped IPv6 规范化为 IPv4 后处理，去掉地址 zone 等本机信息。不做 DNS 查询、地域识别或网络请求。无法解析的地址置空，不影响跳转。

Referer 只接受可解析的 HTTP/HTTPS 来源 host，规范化大小写、合法 IDN 和末尾点后限长；相对引用、about:blank、无 host、非法或超限 host 置空。即使头中携带 userinfo、路径或查询参数，也绝不保留这些部分。UA 与来源均为不可信输入；异常解析不能抛出阻断跳转的错误。若访客随机值或摘要无法生成，跳过该次统计并记录失败，而不是写入一个会污染全部 UV 的公共默认访客。

## 查询契约的具体约定

所有统计查询经管理令牌保护后，使用 MySQL 权威日志，不读取或补写 Redis 统计数据。查询映射存在性只为区分不存在和已有零记录，不按 enabled 或 expires_at 拒绝历史统计；查询与访问采集使用统计专用连接，不借查询接口消耗核心映射连接池。

| 接口 | 结果 |
| --- | --- |
| GET /api/internal/links/{code}/stats | shortCode、from、to、timeZone、pv、uv、uvBasis、collectionPolicy、collectionEnabled、identityVersions、generatedAt，以及每日 date/pv/uv/isOngoing |
| GET /api/internal/links/{code}/visits | 同一短码及日期范围的 items、nextCursor、hasMore；每项含 occurredAt、peerIpNetwork、userAgent、refererHost |

`from`、`to` 都不传时按本次查询的上海日期默认最近 7 天；只传一个、重复参数、非法日期、from 大于 to、未来日期或超出保留窗口返回 400 INVALID_REQUEST，不静默截断。统计窗口包含当日及前 29 日；两端日期均包含，换算为 UTC 的左闭右开时刻范围。当前日标记 isOngoing，不把今天或无记录日期声称为已完整采集。

范围 PV 为匹配日志行数，范围 UV 为整个范围内 `(visitor_key_version, visitor_hash)` 的去重数量；日趋势按 stat_date 分组，各日独立去重。聚合请求在显式的短只读 REPEATABLE READ 事务中完成普通一致性读取，汇总、趋势和身份版本来自同一快照，不用 FOR UPDATE/共享锁。generatedAt 只表示响应生成时间，不宣称精确的数据库提交截止时刻。正常有效日期补零；数据库错误或繁忙不能返回伪造零值。

uvBasis 为 anonymous-cookie，collectionPolicy 为 best-effort。紧急 HMAC 密钥轮换必须更换版本；响应列出范围内观察到的身份版本，多版本时明确 UV 可能因身份拆分增加。UV 在日志标识上准确去重，不等于真实人数或可靠覆盖所有请求。统计启用前或故障期间没有日志不能补采。

明细默认 limit=20，范围 1 至 100，超限、非整数或重复参数返回 400。以 `(occurred_at,id)` 降序分页；游标保存最后排序位置并绑定短码、日期范围和格式版本，解码时严格校验，不用大 OFFSET。游标只控制授权后查询的位置，不是访问凭证；只需结构与范围校验，不以它承诺固定快照。取 limit+1 判断 hasMore，内部行 ID 可放在游标中，不展示访客摘要、密钥或原始 Cookie。

跨页可能发生新写入、窗口移动或清理；新的迟到记录可能不会在继续向后翻页时被看到，返回首页可重新查询。重复发生时间用行 ID 保证稳定顺序；游标对应的行已经清理时仍按排序位置继续，不要求原行存在。跨日使原范围移出保留窗口时返回 400，不维持过期游标的历史访问能力。

| 查询/管理拒绝 | HTTP 与语义 |
| --- | --- |
| 未配置管理令牌 | 404；查询及现有状态接口均关闭，不执行业务 |
| 缺失、错误或重复令牌头 | 401 INTERNAL_UNAUTHORIZED；先于参数/请求体解析，不执行业务 |
| 已鉴权但短码非法或不存在 | 404 LINK_NOT_FOUND |
| 日期、limit、cursor 非法或超窗 | 400 INVALID_REQUEST |
| 统计查询无并发容量 | 503 STATS_BUSY；不伪造结果 |
| 统计查询明确超时 | 503 STATS_QUERY_TIMEOUT；不在请求内重试 |
| 其他统计数据库错误 | 500 INTERNAL_ERROR；不泄露数据库或请求原文 |

各项响应均 no-store。统计 GET 所隐式支持的 HEAD 同样鉴权，不能绕过保护。现有 PUT 通过鉴权后完全沿用 ADR-0005 的 200/404/409/410/503、行锁及三次缓存协调规则，响应结构保持已有契约；特别是重复状态 PUT 不能当作协调恢复。本决策增补 ADR-0005 当时不实现鉴权的范围，不修改其状态语义。

管理令牌建议通过 `SHORT_LINK_INTERNAL_TOKEN` 提供，访客摘要秘密及版本分别通过独立配置提供；不写入仓库或默认页面。令牌精确比较，不 trim、不接受 URL/Cookie 替代、不回显，异常日志不包含请求头。配置轮换是受控管理操作；接口没有按用户/链接所有者授权的能力。部署还应说明统计 Cookie 用途与保留期，并控制在线表和备份的访问；摘要及脱敏信息仍不是完全匿名数据。

## 已确认的清理、配置与测试设计

日志清理与统计采集分开：它是数据库维护，不是异步处理访问。建议应用启动后及每天上海时间 00:10 做过期清理，每批最多 1000 行、每批独立提交，按 stat_date/id 索引删掉窗口外记录。单轮最多运行 30 秒；有积压时后续每 15 分钟继续一轮，直至清空。清理无容量或失败时不在该轮反复重试，记录最旧日志日期和积压并留给下一轮。并发实例重复清理须安全，不新增分布式锁或任务表；进程退出后按过期条件继续，不依赖易丢失的内存游标。关闭采集仍继续清理旧日志，停机期间不声称能清理，恢复启动后重新追赶。单条 SQL 的阻塞仍受统计专用超时约束，30 秒轮次预算不宣称能强制中断任意阻塞。

查询窗口在每次请求开始固定，清理尚未完成也不返回过期数据。物理删除是受资源和故障影响的尽力维护，窗口外记录可能延迟存留；清理延迟应有可观察的积压，不能对外宣称任何故障下超过 30 日的记录已经全部删除。不自动回放访问日志、不重写 PV/UV、不自动管理 MySQL 备份或 binlog 保留。在线删除并不代表所有备份均被删除，实际部署须明确备份保留与访问规则。这里不增加新的用户隐私导出/删除 API。

建议采集可以独立开关，默认关闭：关闭时不生成统计事件/Cookie、不写日志，经过鉴权的查询仍可读已有历史日志，并通过 collectionEnabled=false 明确当前不采集，不能把停采期的零值解释为没有访问；状态管理的令牌保护仍然生效。关闭采集时不要求 HMAC 密钥，但查询与清理仍按各自需求使用统计池。启用采集必须提供有效的独立 HMAC 密钥和版本，不设置示例生产默认秘密。显式非法配置启动失败，运行期的统计依赖故障按跳转优先处理。统计池采用不因连接预检失败而使启动失败的初始化策略、minimumIdle=0，在实际查询/清理/记录时按超时取得连接；统计网络不可用不引入新的启动硬依赖。核心应用原有的数据库初始化依赖仍存在，不宣称已经消除它。开关不承担 Redis 受控恢复职责，也不关闭现有跳转缓存。

### 后续实现的验收测试计划

以下是设计验收计划，不是本轮已经执行的测试结果。

| 场景 | 应证明的结果 |
| --- | --- |
| 逐请求 PV | 同 Cookie 多次合法 GET 各有独立 event_id，PV 为已记录次数、UV 为 1；刷新与客户端重试增加 PV |
| 排除请求 | 非法短码、404/403/410、决定前数据库错误、HEAD、创建、统计查询、状态管理均不写访问日志、不设置访客 Cookie |
| 机器人边界 | 普通 GET 即使 UA 表示爬虫或预览器也按口径记录，不以本版测试宣称真人识别 |
| 缓存命中与 miss | 两条路径都逐请求记录；缓存 hit 不查映射，但仍可写日志，不能再把 hit 描述为完全不访问 MySQL |
| 共享加载并发 | 控制两个请求共享一次映射加载，在统计容量足够时得到两条访问日志；不把加载次数当 PV |
| 访客 Cookie | 首次生成、非法/多值重建、合法复用、不续期、host-only/Path/HttpOnly/SameSite/Secure；HEAD 不生成 |
| Cookie 偏差 | 不回传 Cookie 的多次请求形成多标识；首次并发可形成多标识，测试承认偏高而非伪造稳定真人 UV |
| 维度隔离 | 相同 Cookie 访问两个短码分别统计，摘要不同；两个短码指向同 URL 不合并；短码大小写不同不能混算 |
| 跨日范围 UV | 同访客跨三个统计日，各日 UV=1，范围 UV=1，范围 PV 为所有已记录事件之和 |
| 访问时点 | 最终检查前到期拒绝；用例结果传递冻结时刻，入口不重新读钟；决定后等待到期仍302，跨午夜仍写原统计日；各共享加载等待者各自定时 |
| 状态并发 | 决定后禁用不改变在途 302；管理完成后新请求遵守新状态，旧共享加载/回填继续受版本协议约束 |
| 身份摘要 | 同短码/密钥/版本稳定；不同短码不同摘要；跨实例同配置去重，紧急更换版本显式呈现身份拆分 |
| IP 与代理 | IPv4 /24、IPv6 /48、IPv4-mapped、无效地址置空；伪造 Forwarded/XFF 不改变对端来源，不落完整地址 |
| UA/Referer | 缺失/畸形/控制字符/超长/Unicode/IDN；不保留完整 URI、密码或查询参数；元数据错误不阻断跳转 |
| 数据模型 | 真 MySQL 验证毫秒 UTC、统计日、大小写、字段边界和 event_id 唯一约束；客户端两次 GET 仍是两条事件 |
| 同事件重放 | 相同 event_id 不能新增行或增加 PV；不将其他数据库异常解释为正常去重；不编写尚未存在的 MQ 消费测试 |
| 写入失败 | 注入日志数据库失败，合法跳转仍为 302，失败指标增加，不重试、不改写映射或缓存 |
| 提交结果不确定 | 控制先保存后报错，仍 302、日志至多一条且没有新的重试事件；不能把超时武断解释为未执行 |
| 忙时丢弃 | 受控占满统计许可，其他跳转立即绕过统计并增加 dropped；成功/异常后许可释放；不建立无界等待队列 |
| 连接池隔离 | 确认日志/查询/清理使用统计池，核心创建/状态事务仍用核心池；不以同一 MySQL 的测试宣称硬件完全隔离 |
| 真实超时 | 少量真实 MySQL 断连/锁等待/网络延迟验证配置实际生效；用有余量的有界等待验证，不把 mock 抛异常当作耗时证明 |
| 聚合快照 | 在汇总与日趋势读取之间插入或清理日志，同一只读 RR 请求仍使用同一快照；普通统计读取不锁映射 |
| 查询语义 | 默认7天、完整30天窗口、日期两端包含、补零、今天 isOngoing、禁用/过期可查、真实不存在404 |
| 查询拒绝 | 单端/重复/非法日期、未来/逆序/超窗、非法 limit/cursor 为400；繁忙/超时/数据库错误不能返回0 |
| 游标分页 | 同时刻多行稳定排序、limit+1/hasMore、范围绑定、删除游标行、并发新写、跨页清理及窗口移动，不承诺快照导出 |
| 令牌保护 | 未配404；缺失/错/重复头401；GET/HEAD/状态PUT全部保护，拒绝先于解析且核心 mapper/cache 无调用 |
| 管理回归 | 合法令牌下保留 ADR-0005 的重复409、过期410、并发提交顺序、三次协调、已提交503及仅内部恢复 |
| no-store 与泄露 | 全部查询/管理响应no-store，响应和错误日志无 token、Cookie、visitor_hash 或完整请求头 |
| 清理与窗口 | 首尾日期、启动/每日/积压轮次、批量/预算/失败/无容量、多实例重复清理、关采集继续清理与停机后追赶；查询先过滤超窗数据 |
| 配置与关闭 | 默认/显式关闭采集不写日志/不发Cookie，不要求HMAC密钥，查询读历史并标记停采；统计池网络初始化失败不新增启动硬依赖；非法配置失败、未配令牌不开放管理 |

复用当前 MockMvc、可控 Clock、mapper/cache seam、闩锁同步点、真实 MySQL 8.4 和 Redis 7.2 的 Testcontainers 以及独立应用实例。统计记录器和数据访问只在确需故障注入、控制事件 ID 或容量时提供最小替换边界，不暴露生产测试 HTTP 入口。并发测试控制先后顺序；不靠长 sleep、随机抽样或响应相同来证明去重/一致性。真实超时测试隔离环境，不在生产故障注入。

### 后续引入 RabbitMQ 的铺垫与限制

- 访问事件与 Servlet、缓存对象、映射实体分开；事件携带稳定 event_id、short_code、发生时间、已计算统计日、访客摘要及身份版本、脱敏元数据。原始隐私信息在采集边界消除，后续处理不重新解析浏览器请求或使用处理时刻分桶。
- 逐请求跳转入口调用窄的统计记录边界，当前实现是同步 MySQL 写入；未来可以替换事件提交方式，查询模型和 PV/UV 口径继续明确，不把消息系统装进跳转缓存加载器。
- event_id 唯一约束为后续重复事件去重提供基础。未来若增加汇总表，去重与统计变更须在同一 MySQL 事务完成；不能先标记处理再单独更新计数，也不能在重复事件上再次递增 PV。
- 这不保证事件可靠产生、消息可靠投递或端到端恰好一次。发布确认、消费者确认、重试/死信、乱序/晚到、可靠采集及可能的 outbox 必须在后续阶段重新设计；本版不预建相关依赖、表、线程池、队列、交换器或消费者。
- 30 天清理会删除日志里的事件去重记录；未来允许晚到或长时间重放时必须重审幂等记录保留期、过期事件处理和数据修复。不能直接套用日志唯一约束宣称无限期去重，也不能恢复仅保存日 UV 数字的范围并集。

## 同步资源的已确认起始配置

统计使用指向同一 MySQL 的独立 DataSource 和明确归属的事务边界，不占用短链接映射的连接池。新增统计 DataSource/事务管理器时必须明确核心 mapper、发号和状态事务仍绑定原核心连接，统计 writer/query/cleanup 绑定专用连接，不能依赖出现多个同类型 bean 后的默认推断。建表初始化也须明确只执行一次，不能因增加数据源无意切换核心自动配置。初始总容量 4；建议访问写入并发 2、统计查询并发 1、清理并发 1，均采用立即尝试准入，不将大量 HTTP 线程排队等待容量。准入失败的访问不写日志、计入 dropped；查询无容量返回明确的繁忙错误，清理无容量推迟到后续轮次。成功或失败都释放准入容量，不能因某次异常永久耗尽许可。

| 统计专用配置 | 起始值 | 约束的阶段 |
| --- | --- | --- |
| Hikari connectionTimeout | 1000ms | 取连接等待；不代表 SQL 或 HTTP 总耗时 |
| Hikari validationTimeout | 500ms | 连接验证；低于取连接预算 |
| Connector/J connectTimeout | 500ms | 网络建连 |
| Connector/J socketTimeout | 1000ms | socket 网络操作 |
| JDBC Statement 查询超时 | 1 秒 | 写入及查询语句执行；必须验证实际生效 |
| 统计会话 InnoDB 行锁等待 | 1 秒 | 数据库行锁等待；只设置统计连接，不全局改动 |

这些是已确认的可配置起点，不是压测结果或整个调用的墙钟上限。Hikari 等待超时最低 250ms，不能把 Redis 的 200ms 直接套用；事务 timeout、语句取消及网络错误也不能证明数据库没有执行写入。连接失效、提交确认丢失、线程调度及多个网络操作仍需用真实数据库故障验证。同步版本不会增加统计重试、异步执行器、RabbitMQ、Redis 队列或后台访问补偿。

运行时观察访问事件尝试数、确认保存数、繁忙丢弃数、写入失败及结果不确定数、统计耗时、查询超时、连接池占用和清理积压。指标不以短码、IP 或访客标识作无限增长的标签。错误记录只包含事件 ID、受控错误类别和所处阶段等定位信息，不包含管理令牌、Cookie 或原始请求元数据。

## 已确认的存储取舍：第一版直接查询 MySQL 日志

Redis Counter 适合高频整数递增，可作为 PV 的实时聚合结构。单个 `INCR` 不会因并发读改写而丢掉递增，但它不去重访问事件；命令超时后重复执行可能计两次，Key 被淘汰、过期或丢失也不能据此证明历史 PV 为零。若未来采用按日 Counter，还需明确日界线、Key 生命周期、持久化和恢复来源。

Redis HyperLogLog 适合只需要近似去重数量、访客基数较高的 UV 查询。重复加入同一个标识不会使集合多一个成员；不同访客身份策略仍会影响统计偏差。`PFADD` 的返回值表示结构是否改变，不是可靠的“新增一个 UV”标志。跨日范围应合并 HLL 后估算并集，不能相加每日估算值，也不能只把每日 UV 数字持久化后声称可恢复范围 UV。HLL 不提供访客名单或可靠的单成员删除能力，不代替逐条访问日志。

本阶段选择 MySQL 日志权威：同步插入日志后直接查询 `COUNT` 和范围内的访客去重，日趋势也从同一数据来源产生。查询在已保存日志上按访客标识准确去重，但 Cookie 偏差、漏记和提交结果不确定仍然存在。本轮不把 HLL 的算法标准误差和故障漏记混为一种误差。

采用 Counter/HLL 不会消除同步日志写入；额外统计双写还需处理一个存储成功、另一个失败以及修复与新写入并发。因此第一版不存 Redis 统计数据、不增加每日汇总表、去重表或 Redis 统计查询缓存，具体日志模型已经确认。所有访问明细及统计依据都存 MySQL，现有跳转映射缓存继续存 Redis。该选择接受日志增长、索引写入、范围聚合及每次同步数据库提交的成本，适合当前尚未承诺吞吐目标的第一版；后续凭访问量、写入延迟、查询延迟和存储体积再评估投影或异步采集。

## 已核实的技术事实

- Redis `INCR` 是整数计数操作，适合计数器；单条命令的计数能力不等于每次 HTTP 请求都可靠记账。重复执行、超时结果不确定以及存储丢失仍需设计处理。
- Redis HyperLogLog 估计集合基数，单个结构使用至多约 12 KB，标准误差约 0.81%；这不是每次查询的最大误差保证，也不包括 Key 等额外开销。
- HyperLogLog 的输入必须先明确访客身份。换用它不会自动修正 IP 无法对应一个人的问题。
- 时间范围内的 UV 不能通过每日 UV 数值相加取得；应对范围内访客身份的并集去重。本版从 MySQL 日志直接做范围去重；去重集合或 HLL 合并仅为其他方案的知识讨论。
- 返回 302 不能证明客户端实际跟随重定向并打开目标网站。PV 的采集时点必须说明服务端所能观察的边界。
- Referer 可能缺失或只含来源站点，缺失不能证明一定为直接访问；User-Agent 和 Referer 都不是可信的身份或授权依据。
