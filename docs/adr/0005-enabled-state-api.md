# 内部启用/禁用接口拒绝重复操作，提交后有限重试缓存同步

内部管理者需要替代直接 SQL 的状态维护入口，用户已确认通过单个 PUT 接口设置启用状态，并选择过期后禁止任何状态操作、重复操作返回 409，而非重复成功。状态判断与更新在 MySQL 行锁事务中完成，按数据库提交顺序生效；沿用 ADR-0004 的提交后版本轮换协议，只有缓存同步确认后才返回完成，防止旧结果迟到回填。

## 与现有决策的关系

本决策增补 [ADR-0004](0004-negative-cache-for-redirects.md) 当时不增加维护 HTTP API 的范围。已禁用与已过期仍独立，跳转判断保持过期优先；新的管理接口禁止过期后改状态，不改变缓存类型、版本协议、条件回填或故障恢复边界。历史 SQL 维护允许写字段，并不代表新接口允许该业务操作。

## 取舍与后果

- 请求内缓存同步总共最多三次，两次重试前分别等待 50ms、100ms；只重试同步，数据库状态只更新一次。旧操作即使晚于新的反向操作完成重试，也只能使缓存重新读取当前 MySQL 状态。
- 用户选择有限同步重试，暂不采用后台持续补偿或持久恢复记录，以控制实现范围。耗尽返回带短码的 503，明确数据库已提交但同步未确认；长时间故障或进程退出不保证自动恢复，仍保留既有内部协调恢复方法。
- 重复状态请求返回 409，不能用于恢复上一请求的未确认同步；超时可能发生在 Redis 命令已经生效之后，协调恢复可以安全重复。响应中的 enabled 代表本次提交结果，不保证没有后续状态操作。
- 等待中断时保留线程中断标记，停止尝试并报告同步未确认；单次 Redis 超时与等待间隔不构成整个请求耗时上限。数据库提交未确认不执行缓存协调，也不报告已提交的部分完成响应。
- 此接口用于受信任内部管理，不新增页面、鉴权、归属模型或表，不扩展创建接口的重试策略。

用户于 2026-10-01 确认上述方案，之后授权按本地规格执行。
