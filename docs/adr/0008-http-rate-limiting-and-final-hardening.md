# 阶段 8：按请求组限流与可复现工程化收尾

本 ADR 记录 `/grill-with-docs` 讨论。用户已确认 Q1～Q23，并于 2026-10-04 通过 Q24 确认完整共识，状态为 accepted；这不代表已实现或获得开发授权。完整方案见 [最终设计](../final-hardening.md)，逐轮讨论见 [阶段 8 地图](../../.scratch/final-hardening/map.md)。

## 已确认的目标与范围

继续允许匿名创建；防护目标为减少创建滥用、短码扫描和高频管理操作的资源压力，不承诺抵御大规模分布式攻击，不扩展账号、验证码或完整反滥用平台。

Prometheus/Grafana 非必交付，不引入 Spring Cloud、Kafka、Elasticsearch、Kubernetes。

## 已确认的限流方案

复用现有单节点 Redis，使用一个短且有界的 Lua 令牌桶实现；按请求组配置不同的桶容量与补充速率。创建从严、跳转宽松，不实现多套算法。固定窗口存在边界集中通过的问题；滑动窗口日志更精确但状态更多；令牌桶支持控制突发和持续速率，但不能描述为严格的任意滚动时间窗次数上限。

| 请求组 | 维度 | 限流依赖失败 |
| --- | --- | --- |
| POST /api/links | 连接对端 IP | 进入发号与写库前 fail-close，独立 503 |
| GET/HEAD /s/{code} | 连接对端 IP，跨短码共享 | fail-open，继续原跳转流程 |
| PUT /api/links/{code}/enabled | 鉴权后固定共享管理写分组 | 进入业务前 fail-close，独立 503 |
| GET/HEAD /api/internal/links/{code}/stats、/visits | 鉴权后固定共享管理查询分组 | 进入查询前 fail-close，独立 503 |

不使用匿名 UV Cookie 作为可靠防刷身份，不将原始管理令牌放入 Redis Key，不新增逐短码额度。管理鉴权先于限流，未配置与无效令牌维持原有 404/401。静态页面与健康检查不占用业务额度。

限流与缓存使用不同 Key 命名空间，但复用同一 Redis 仍共享故障与资源压力。Lua 将读取、补充、判断和扣减串行执行，防止并发重复消耗同一令牌；它不提供 MySQL/Redis 联合事务、失败自动回滚或跨故障永久配额承诺。

## 已确认的起始参数与准入边界

| 请求组 | 桶容量 | 补充速率 |
| --- | --- | --- |
| 每 IP 创建 | 3 | 每 6 秒 1 个 |
| 每 IP 跳转 GET/HEAD | 60 | 每秒 10 个 |
| 共享管理写 | 5 | 每秒 1 个 |
| 共享管理查询 | 5 | 每秒 1 个 |

所有参数可配置，只是本地验收起点，不是压测证明的安全容量。创建在请求体解析前限流；跳转先做廉价格式校验，非法格式沿用 ADR-0004 返回 404、不访问 Redis/MySQL，合法格式在查询缓存或数据库前限流；管理先鉴权再限流。获准请求扣一个令牌，后续参数/业务/依赖失败不退还；无令牌的拒绝不扣成负数。

429 使用 RATE_LIMIT_EXCEEDED、向上取整到秒的 Retry-After 和 Cache-Control: no-store；HEAD 无响应体。限流或回源保护拒绝不设置统计 Cookie、不生成访问事件、不计 PV/UV。正常 GET 跳转与 HEAD 的原有统计边界保持。

Redis TIME 用于补充时间，闲置状态 TTL 不短于空桶补满时间；TTL 清理不保证全局内存上限。参数化脚本与 EVALSHA/NOSCRIPT 重载用于正常执行；不确定的扣减超时不盲目重试，按对应请求组故障策略处理。接受重启/清理/淘汰导致额度重置，不增加幂等扣费或持久化限流历史；限流重置不替代已有跳转缓存受控恢复协议。

## 已确认的回源保护

Redis 无法确认缓存版本时不参与现有同码加载合并，多个合法但不同短码也不能共享同一次查询，因此给实际跳转数据库加载增加每实例并发准入：起点 4、可配置，正常 miss 与故障回源均适用；缓存命中和共享任务等待者不占用，真实查询完成或失败后释放许可。无许可立即返回独立 503，不增加等待队列，不计 PV。Redis 限流 fail-open 只放行限流阶段，仍受回源保护约束。

该上限不是集群全局上限，不保证 HTTP 总耗时，也不隔离所有 MySQL 工作负载。不增加第二套本地每 IP 限流。

## 已确认的工程化范围

初始化包含数据库与既有 MQ policy，重复启动不删数据/积压。应用仅以核心 MySQL 健康为启动硬依赖；完整演示仍核验全部组件，healthcheck 不等于运行期自动恢复。

基础配置管理令牌无默认值，统计采集默认关闭，启用采集必须配置有效独立 HMAC 密钥。密钥在重启之间保持稳定，消费者默认开启，停采不停止历史消费。密钥轮换与数据重置分别说明。

Actuator 的 liveness 只判断自身，core readiness 检查应用就绪和核心 MySQL；Redis/MQ/统计另列依赖或功能状态，不成为 core readiness 硬门槛。Redis 故障时核心就绪不保证创建/管理可用。管理端口隔离，仅 health/info/metrics，主端口只给无详情存活/就绪探针；禁用 env/configprops/heapdump/动态日志修改等。必要指标覆盖 HTTP 次数/耗时、限流/回源拒绝、缓存、已有 MQ 终局/积压观察与池状态，标签限制为请求组与固定结果类别，不含 IP/短码/URL/访客标识。

日志标准输出使用服务端 requestId、安全操作/结果类别及必要耗时。记录启动停止、依赖降级恢复、已提交但缓存协调未确认、MQ/清理失败；仅必要定位故障使用短码。成功跳转不逐条 INFO，高频拒绝汇总或有界采样。原始 URL/查询串/请求体/令牌/Cookie/秘密/访客摘要/原始 IP/完整 Referer 或 UA/MQ payload/未经安全处理的依赖异常不得进入普通日志，保留并验证现有安全编码器；不添加日志平台。

API 文档使用兼容 Boot 3.5 的 springdoc OpenAPI 与本地 Swagger UI，不内置或持久保存真实令牌，不把 Actuator 放入业务 API。明确管理鉴权、HEAD/统计口径、429/Retry-After、限流失败/回源繁忙/已提交协调未确认的不同 503，以及重复创建可能新增映射的边界。README 保留最短运行与演示路径，详细契约另页。

## 已确认的资源、验收与展示

核心 Hikari 起点 max8/连接获取等待500ms，统计池原max4与准入2/1/1保持，实际跳转回源max4不等于独占预留连接。Redis内存满时按相关操作失败及已有降级规则处理，不静默淘汰限流桶；保持原短超时，本阶段不增加自动熔断/故障冷却。

CI运行必需回归与新增并发限流、TTL/脚本/故障、回源许可、HTTP/统计无副作用、秘密/健康/日志隐私、API文档及启动/卷/policy验收，缺设施不静默跳过，不追求机械100%覆盖率。有限性能观察明确环境/并发/样本/额度并区分业务成功、429、503，不预设万级QPS或生产SLA。

README首页保留目标/实际能力、截图/技术栈、架构图、初始化运行/演示、API/测试入口和故障局限；详细设计/运维与必要证据放正式docs。目标图展示单Spring Boot进程、MySQL权威/Redis缓存与限流、MQ同步/异步边界、有界缓冲/DLQ/端口和卷；时序图说明Lua原子性及已提交/协调未确认。简历围绕发号编码、版本缓存及并发防护、有界异步统计和幂等消费、验收后的Lua分组限流/回源保护；新增能力未实施验收前只列计划。

## 与现有决策的关系

本阶段增补 ADR-0004 当时暂不实现限流的范围，保留其版本化缓存与受控恢复协议。限流故障时的跳转放行不代表 MySQL 能承受全部流量；回源保护新增负载过高时的拒绝边界。

限流失败的创建 503 发生在业务之前，必须与 ADR-0004/0005 已提交但缓存协调未确认的专门 503 区分，不能误报映射已保存。管理鉴权边界保持，统计仍沿用 ADR-0006/0007 的已记录事件口径和 best-effort，不将统计或 RabbitMQ 的故障变为核心跳转硬依赖。

当前 application.yml 中已提交的管理令牌与访客 HMAC 默认值相同、默认开启采集，与文档声明冲突。已确认采用上述独立秘密和默认关闭规则作为修复方案；本文仅为设计，不代表已修复。
