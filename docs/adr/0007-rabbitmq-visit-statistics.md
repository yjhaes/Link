# 阶段 6：RabbitMQ 异步访问统计

当前同步统计已有独立池、写准入、超时及失败降级，但获准写入仍让HTTP线程等待JDBC，繁忙时直接漏记。以有限规模学习及隔离统计写入为目标，选择引入最小RabbitMQ方案；没有生产性能证据证明MQ是业务必需品。相较保留同步或只做进程内异步，独立broker可以缓冲短期尖峰并分离发布/消费边界，代价是broker维护、异步可见性及消息失败处理，因此不扩展成复杂消息平台。

请求内完成核心跳转判定、匿名Cookie、HMAC、最小化元数据及逐请求事件冻结，作出跳转决定后尝试本地有界交接，HTTP不等待统计网络或数据库；后台Producer发布，同应用独立统计listener写MySQL，不拆微服务。采用单节点RabbitMQ、分离发布/消费连接、一个durable direct业务Exchange/一个durable classic业务Queue，消息持久化；追加单一DLX/DLQ供排查，无自动回流。UTF-8 JSON继承已有九个事件字段并增加schemaVersion=1，不传浏览器原始标识、秘密、请求对象、映射或缓存实体。同进程/同MySQL仍共享资源，单节点持久队列不构成高可用承诺。

跳转优先，统计best-effort；缓冲满、发布失败/不确定及进程退出等允许漏记，失败事件不自动重投，不同步回退MySQL，不新增outbox或可靠记账承诺。correlated confirms和mandatory/returns用于观测投递，不表示数据库保存。Consumer使用同步listener与Spring AUTO，持久化边界明确已保存/仅eventId重复或传播失败，复用数据库唯一键；暂时错误每轮最多3次（含首次，重试间隔200ms/500ms），永久错误不重试，最终拒绝且不requeue。明确本地缓冲、未确认、channel、prefetch和队列容量/TTL；发布观察及恢复独立且有界，只重建发布连接。数据库持续故障采用观测和人工暂停消费。

MySQL访问日志继续作为统计权威，正常数秒可见为起始目标，故障或积压期间没有固定延迟保证。冻结的发生时间/上海统计日不因迟到或映射当前状态变化而修改；已超出最近30日窗口的合法事件确认丢弃，未来统计日拒绝，人工重放同样检查窗口。MQ声明和listener启动在核心启动后后台执行，MQ不成为新增核心启动硬依赖；关闭采集只停止新事件/Cookie，历史消息消费、查询和清理继续，人工暂停消费与自动连接恢复意图分开。停机等待有界，不把进程内未发事件当可靠存储。
